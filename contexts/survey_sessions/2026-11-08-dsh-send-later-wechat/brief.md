## 读者

让 AI coding agent 长时间跑任务的程序员，很多人在用按小时刷新额度的订阅（如智谱 GLM Coding Plan）。他不一定知道 DeepSeek Harness（DSH）是什么，文章第一次提到时用一句话交代清楚。他此刻已经在关心的问题：任务跑到一半被 429 打断，人不在电脑前，会话就停在那里；发了 PR 之后还得自己记着回去看回复。

## 入口方案（比较后选 A）

- 方案 A（场景痛点）：任务跑到一半突然 429，额度五个小时后才恢复，人又不在电脑前。门槛测试：读者只需满足一条前提，让 agent 跑过长任务。入口在正文全部兑现（续跑场景、查 PR 场景、联动技巧都是正文内容）。选中。
- 方案 B（设计叙事）：给 DSH 写插件时我面临一个选择，自建定时循环还是用官方自动化。门槛测试：读者需要同时知道 DSH 是什么、且关心插件设计，超过一项。降级为第二节的展开方式，不做入口。

## Thesis（一句话，可证伪）

dsh-send-later 没有自建定时队列，把延时发送整个架在 DSH 官方自动化任务上，这让定时消息重启不丢、能在官方界面统一管理，也是「额度恢复后自动续跑」这类玩法能成立的前提。

## 信息增量

README 只列功能清单。本文第一次给出：两个真实使用场景（429 续跑、24 小时查 PR）、quota-watch 联动的「恢复时刻 + 2 分钟」技巧、以及为什么借官方自动化而不是自建循环的设计权衡。已核对作者近期归档（2026-09-26 两篇 Copilot 拆解），无选题重复。

## 单一带走点

让会话到点自己收到一条消息，就能把卡住的任务捡回来；实现方式是借用宿主官方的自动化能力，不是再造一个轮子。
