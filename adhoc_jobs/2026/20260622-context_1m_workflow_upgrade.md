# 1M 上下文重塑的双 Agent 闭环协作新范式

这是在最近 GLM-5.2 模型开放 1M 超长上下文的前提下，我在进行 ob-harness（一个面向 OpenBMC 固件开发的工作平台框架）开发迭代时，琢磨并实践出的一套全新协作范式。

在正式展开具体流程之前，先将常驻且调试稳定的双 Agent 详细配置交代如下，以便建立统一的讨论底座：

- **主力 Agent**：Claude Code（搭载 GLM-5.2 Max [1M]），负责理解工程上下文、起草方案与分步计划，并执行具体的代码改动。
- **顾问 Agent**：GitHub Copilot（搭载 Claude Opus-4.8 Max [1M]），负责方案的多维审计、对抗评审，以及整合质量报告。

超长上下文的工程质变不在于单次读取信息的多寡，它直接重塑了主力 Agent 与顾问 Agent 之间的交互频次与校准深度。有了 1M 超大上下文的支持，过去因窗口限制而无法实现的多轮辩论、反驳与深度评审，现在能够在一个稳定的会话中安全沉淀。

在传统的短上下文模式中，一旦进行多轮高密度的方案修正和步骤规划，通常不超过两三轮交互，先前建立的设计背景就会因为信息溢出而丢失，导致后续的实施步骤发生严重漂移。这使得人类必须扮演昂贵的记忆中介，频繁介入和校准。随着超长上下文时代的到来，执行端与评审端得以在单次会话里共享全量上下文，把开发过程推进为多 Agent 之间的自我进化系统。

在这种大容量的协作界面中，已经沉淀出一套能够大幅消除执行摩擦的「多 Agent 闭环决策博弈」工作流。根据底层方案的成熟度和协作阶段，这套工作流通过两类不同偏重的方案整理与设计澄清工具（起点）进行输入：

### 起点：构建设计方案的两类前置澄清路径

在一项复杂工程落地前，人需要与主力 Agent 进行前置的设计方案讨论与澄清。根据业务初始约束的完整度，这对应着同一种工作流下的两种头脑风暴与共识形态：

- **路径 A：`/brainstorming`（模糊诉求的收敛与方案设计）**：在需求尚不完全明确、或面临多方案抉择时开启。它主要用于在 Phase 1-4 中澄清目的、比较 trade-offs，将零散的想法收敛成一份界限清晰的多方案对比报告，并在 Checkpoint A 获得方向批准后，输出一份格式规范的、落盘的设计 Specs（设计说明书）。
- **路径 B：`/grill-with-docs`（已知方案的极限拷问与规约输出）**：当用户已经有了初步的设计底稿或相对确定的思路，但需要高强度排查隐藏隐患时开启。这是一种由 Agent 驱动的、极具对抗性的头脑风暴形态。Agent 会扮演严苛的同行评审人，通过无情且连续的追问（relentless interview），逼出设计盲区、性能边界以及异常处理逻辑。在这个逼问与防御的博弈过程中，不仅方案被大幅磨练，Agent 还会顺带自动输出 ADR（架构决策记录）与领域的 Glossary（领域词汇表）。

### 核心：博弈论证与闭环执行流

无论是通过路径 A 的多维权衡来理清线索，还是通过路径 B 的严苛追问来逼出隐患，一旦设计方案在第一阶段达成口头或书面共识（Specs / ADR），整个工作流将无缝并轨到相同的「计划编写、多轮博弈、自主执行」标准化执行流中：

1. **计划起草**：主力 Agent 基于已通过评审的设计方案或 ADR，调用 `/writing-plans` skill 分步理清操作步骤，撰写出带有明确测试和验证命令的分步实施计划。
2. **多波次对抗评审**：
   - 顾问 Agent 深度评审主力 Agent 的实施计划，并提交评审报告。
   - 主力 Agent 吸收评审报告中合理的部分，而针对不妥或与实际代码环境不合的部分提出论据扎实的反驳。
   - 顾问 Agent 接受逻辑成立的反驳，结合整体上下文二次校对标准，再次提交评审报告。
   - 这一交叉博弈循环往复，直到两者在具体事实和测试路径上达成完全一致。
3. **高确定性落地（坐等上菜）**：方案和计划双重锁定、并获得人类的最终签字授权后，主力 Agent 在本地环境平稳驱动执行。最后还可以选择性地让顾问 Agent 对执行成果进行一波质量验收。

过去我们需要在双 Agent 协作中频繁充当判断裁决者，现在两个全知维度的 Agent 能够基于长链路信息实现自我纠偏。这种开发范式的代价低且产出具有高确定性，把人的注意力资源完全释放到品味与最终验收中。

---

### 摘要

本文探讨了 1M 超长上下文技术对双 Agent 协作模式的重配。主力 Agent（GLM-5.2 Max）与顾问 Agent（Claude Opus-4.8）在超大上下文支撑下，突破了 ob-harness 复杂固件工具链开发中的沟通瓶颈。通过前置共创（`/brainstorming`）与极限拷问（`/grill-with-docs`）等收敛路径，在无损上下文的状态下进行多轮无干预的理性论证、对抗评审与自主构建流程（`/writing-plans`），由此将传统的“单向对话组件”升级为极低摩擦、自我纠偏的人机闭环共创体系。
