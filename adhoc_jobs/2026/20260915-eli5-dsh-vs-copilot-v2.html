DeepSeek Harness vs GitHub Copilot

给熟悉 Copilot 的工程师：从「编辑器里的助手」到「一切皆插件」

官方公式说 Agent＝模型＋harness：模型出智力，harness 把智力接上文件、终端、网页和其他 agent——记录它做了什么、限制它能做什么。在这一层上，Copilot 是一台出厂装好的整机（家族齐全、开箱即用），DSH 是一块官方给了推荐装法的洞洞板——一切皆插件，插拔自由。

切面一 · 宿主：产品家族 vs 一块内核的四种形态

Copilot 是一个产品家族：同步的 agent mode 住在你编辑器里，异步的 coding agent 租 GitHub 云端的临时工位（单仓库单 PR、一次最长 59 分钟），Agent HQ 再把各家第三方 agent 接进同一座指挥台。DSH 反过来只有一块内核，靠不同插件组合出网页、终端、无界面、自动化四种形态——跑在你自己的常驻机器上。

切面二 · 节奏：同步副驾 · 异步外包 · 常驻任务单

Copilot 官方就分成两档节奏：agent mode 是坐你旁边的副驾（同步、你在场、秒级回合），coding agent 是外包单（异步、云端临时环境、干完发 PR 找你验收）。DSH 把这几件事装进同一个宿主——交互轮次、后台任务、跨轮续跑的目标单都是同一棵插件树的不同用法，跑的是你自己的机器，没有钟点房的 59 分钟上限。

切面三 · 权限：以确认为中心 vs 以系统约束为中心

Copilot 的安全模型以『确认』为中心：agent mode 每个终端命令找你签字，云端 agent 靠临时环境隔离和企业策略兜底。DSH 把安全做成贯穿配置到日志的系统约束：文件、终端、子进程共用一层沙箱，提权必须带理由，被守卫拒绝的操作任何插件都放不回来，拿不准就整体拒绝（失败关闭）。

切面四 · 记忆：便签备忘录 vs 行车记录仪

Copilot 的记忆是『贴便签＋备忘录』：指令文件常在，Copilot Memory 替它记住仓库的细节。DSH 的记忆是一台行车记录仪：模型看见过的一切都进一条只追加的事件日志，续跑、分叉、回放都是同一盘录像带的播放操作——出错时能精确回答『模型当时看见了什么』。

切面五 · 多智能体：舰队指挥台 vs 车间班组

到了多智能体，两家方向也不同：Copilot 做的是舰队指挥台——Agent HQ 把各家第三方 agent 编进同一座 mission control，用 issue 和 PR 当统一接口，平台管调度和治理。DSH 是车间班组——主智能体在自己这台机器里拉群派活，子智能体按作用域领工具和权限，workflow 用一段脚本排班并行。

切面六 · 定制深度：行为层 vs 器官层

扩展生态两家都有市场（VS Code 扩展＋MCP Registry vs dsh 插件包），真正的差别在定制深度：Copilot 让你定制到『行为层』——指令文件、自定义 agent、MCP 工具。DSH 让你 patch 到『器官层』——默认配置约 490 行逐行可覆盖，连 Agent 循环本身都只是可替换的默认插件（创造模式里 agent 甚至能给自己热插零件）。

收尾 · 回到全景：一张表复述全程

从表顶读到表底，就是 AI 编程工具的两条演化路线：Copilot 把各家 agent 编成一个开箱即用的平台家族，DSH 把一个 agent 拆成一切可换的开源洞洞板。这仍不是优劣题，是位置题——要最快上手、深度绑定 GitHub 流程，用 Copilot；要把 agent 的每个器官攥在自己手里，上 DSH。
