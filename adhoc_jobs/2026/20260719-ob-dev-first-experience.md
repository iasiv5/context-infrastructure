# ob dev：一句 Prompt 让 Agent 开改 OpenBMC 源码 

之前的 1.0 到 1.2 版本，ob-harness 主要在负责周边统筹——搭环境、拉代码、跑编译、起模拟器。老实讲，只要没触及核心业务代码，它就始终停留在外围辅助的层面。

这次新增的 `ob dev` 命令组，终于让 Agent 把手伸进了 OpenBMC 的源码深水区。为了直观展示这种开发跨度，今天我们跳过枯燥的架构理论，直接看一个全真案例：

仅凭一句话诉求，看看 Agent 是如何自动跑完“修改源码 → 编译验证 → patch 落盘 → QEMU启动验证”的极客工作流。

---

随后，它自动检索出源码中的 3 处遗留 Logo，跟人类确认作用域。

## 写在最后：破壁之战

虽然换个 Logo 只是玩具级别的 Demo，但这是历史性的一步——AI 与 OpenBMC 源码之间的开发壁垒被彻底打通。

新版引入的 6 个子命令（list / modify / refresh / reset / status / finish），首度把繁琐的 Yocto devtool 工作流，转译成了对 Agent 完全透明的可用 API。

自此，不论是去修补 Jira 上抓取的新 bug，还是新增一个 IPMI Sensor，ob-harness 都能从容潜入代码区了。它不再是帮你准备开发坏境的打杂助手，而是真正坐在键盘前陪你输出逻辑的 **AI 合伙人**。
