DeepSeek Harness vs GitHub Copilot

写给用过 Copilot、刚听说 DeepSeek Harness 的工程师

官方公式写的是 Agent 等于模型加 harness：模型出智力，harness 接上文件和终端、管住手脚、记好流水。两家都做 harness，差别在形态，Copilot 是一台装好出厂的整机，买来就能开；DSH 是一块洞洞板，元件随插随拔，官方只给了一套推荐装法。

切面一 · 宿主：四个入口 vs 一块内核

Copilot 这边是一个产品家族：agent mode 住在你编辑器里，coding agent 租 GitHub 的云端工位，一次最长 59 分钟，Agent HQ 又把各家第三方 agent 请进同一座指挥台。DSH 那边只有一块内核，换几组插件就装出网页、终端、无界面、自动化四种形态，机器是你自己的，一直开机。

切面二 · 节奏：副驾、外包单和常驻任务

Copilot 官方分成两档：agent mode 是坐在旁边的副驾，你在场，一轮几秒到几分钟；coding agent 是外包单，你派完活就走，它在云端干完发 PR 等你验收。DSH 把交互、后台、长目标装进同一个宿主，跑在自己的机器上，跑多久都行，断了还能从断点接着来。

切面三 · 权限：逐扇门签字 vs 分级门禁

Copilot 的安全靠确认：agent mode 每条终端命令都找你签字，云端 agent 用临时环境隔离，企业再用策略管住谁能用什么。DSH 把安全做进了系统本身：文件、终端、子进程共用一层沙箱，越界要带理由审批，守卫拦下的事没有插件能翻案，拿不准就直接拒绝。

切面四 · 记忆：便签备忘录 vs 行车记录仪

Copilot 记事靠便签和备忘录：指令文件常驻，Copilot Memory 替它记住仓库细节。DSH 装了台行车记录仪：模型看见过的一切都写进一条只增不改的日志，续跑、分叉、回放都是播放这盘带子的不同方式，出了问题能查到它当时到底看见了什么。

切面五 · 多智能体：舰队指挥台 vs 车间班组

多智能体这一层两家走了两条路：Copilot 搭起舰队指挥台，把各家 agent 编进同一个 mission control，issue 和 PR 就是通用接口，调度和治理都归平台。DSH 更像车间班组，主智能体在本机拉群派活，子智能体按作用域领工具，workflow 拿一段脚本当排班表。

切面六 · 定制深度：行为层 vs 器官层

两家都有扩展市场，Copilot 靠 VS Code 扩展和 MCP Registry，DSH 靠 dsh 插件包，分野在定制深度。Copilot 定制到行为层，写指令、建 agent、接工具；DSH 能 patch 到器官层，约 490 行默认配置逐行可换，agent 循环本身也只是默认插件，创造模式里它还能给自己热插零件。

收尾 · 一张表看完全部差别

从上往下读这张表，两条路线就清楚了：Copilot 把各家 agent 收进一个开箱即用的平台，DSH 把一个 agent 拆成处处可换的开源洞洞板。要快速上手、深度绑定 GitHub 流程，Copilot 顺手；要把 agent 的每个零件握在自己手里，DSH 对路。
