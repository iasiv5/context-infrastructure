## 一、系列定位

不要写成「我的五个插件」。五个插件各自单薄，合成一条主线才立得住：

**把 DeepSeek Harness 从一个聊天窗口，装修成一个真正的工作站。**

五篇恰好对应工作站的五层，天然形成连续剧结构：

| 期 | 插件 | 层 | 一句话 |
|---|---|---|---|
| 1 | dsh-m | 分发层 | 先有货架，后有生态 |
| 2 | dsh-skins | 感知层 | 工具长成你的样子 |
| 3 | better-sidebar | 操作层 | 聊天窗口长成 IDE |
| 4 | copilot-auth | 接入层 | 接通公司发的电 |
| 5 | skip-browser-auth | 信任层 | 安全地拆掉一道安全检查 |

系列名候选：

1. 「给 DeepSeek Harness 装修」系列（推荐：装修隐喻贯穿五篇，每篇是一道工序）
2. 「DSH 插件五讲」
3. 「Harness 扩展手记」

第一篇必须承担定调任务：文末放「五件套地图」（本期系列总览图），让读者从第一分钟就知道这是连续剧，并且知道下一期有什么。

## 二、每篇立意与大纲

### 第 1 篇 · dsh-m《先有货架，后有生态：我给 DeepSeek Harness 开了家应用商店》

- 立意：生态基础设施视角。插件存在但没人发现、安装靠敲命令、升级靠运气，这是所有插件生态萌芽期共同的天花板。dsh-m 的答案是：收录、安装、卸载、升级全部本机完成，还把这件事同时交给人（侧栏面板）和 agent（7 个 dshm_* 工具）。
- 叙事线：npm 手敲命令装插件的繁琐（痛点）→ 侧栏市场实拍（用户已有截图可作首图）→ 自定义 registry 是真正的护城河（团队内部源、覆盖官方清单、CI 校验）→ 安全基线（integrity 校验 fail closed、GitHub 源锁 commit SHA）。
- 差异化干货（只有作者写得出的内容）：
  - registry 获取链路四层回退：raw @main → jsDelivr → 60 分钟缓存 → 包内快照。收录更新与插件发版解耦的设计动机。
  - 为什么 GitHub 来源只跟踪 release/tag 而不是 main HEAD（FAQ 里那条）。
  - 1,000 条清单也只探测当前页的服务端分页取舍。
- 亮点交互素材：对话内对 agent 说「装 dsh-skins」→ dshm_search 出卡片 → 一键安装的完整录屏/GIF。

### 第 2 篇 · dsh-skins《一键换脸：给 AI 工作台一点场所感》

- 立意：视觉钩子篇，保系列留存。观点：每天盯八小时的工具，值得长成你的样子；皮肤不是美化的花边，是「场所感」。
- 叙事线：五款皮肤实拍轰炸（美人志 / 天官赐福 / OpenBMC / UEFI Harness / 官方）→ 个性化三件套（壁纸、中英标语、通透度单值联动三层）→ URL 切肤 `/?skin=tgcf` 这种小彩蛋 → 配置为什么不会丢（数据目录与安装目录物理隔离，恢复模式保图库）。
- 必须保留的边界声明：美人志、天官赐福为非官方粉丝作品，壁纸为 AI 生成粉丝画作，与版权方无关联未获授权。公众号传播场景比 GitHub 更容易出圈，这段声明要放在显眼位置，直接复用 README 措辞。
- 归属待确认：你把这款列为非自研。若实际为维护/接管（仓库在 iasiv5 名下），本文按「维护者视角」写，重点讲个性化与安全设计；若确为他人作品由你代为推广，按「重度用户评测」写并注明出处。大纲两种角度通用。

### 第 3 篇 · better-sidebar《当聊天窗口长成 IDE：一个第三方插件做到的事》

- 立意：生态观察篇，换视角。前两篇是「我做的」，这篇刻意写别人的作品，恰好证明第一篇的论点：货架建起来，生态自然来。对 omdsh-dev 的作品做深度评测+致敬，同时给 dshfind、GitHub topic 等三方渠道引流。
- 叙事线：默认侧边栏 vs 工作台对比图 → 双工作台（右侧栏+底部面板+自由窗口）→ 真实终端（node-pty，不是模拟器）→ 文件变动双视角（Git + 本轮文件）→ 侧边对话 → 最重要的一张牌：`ctx.betterSidebar` 服务化，内置 8 tab 与 28+ 生态插件走同一套 registerTab/registerFileViewer，能力完全对等。
- 观点升华：better-sidebar 是 DSH 插件生态「二次扩张」的底座。你在 dsh-m 里收录它，和作者开放服务扩展点，是生态两层结构的互文。
- 写法建议：找作者要一两个设计决策的幕后故事（比如聚合包双挂载自动退让、懒加载 325KB 核心的取舍），访谈体比评测体更有传播力。

### 第 4 篇 · copilot-auth《用公司发的 Copilot 订阅，喂饱你本地的 agent》

- 立意：最抓职场读者的一篇。观点：好插件不重新造轮子，只把内置但没启用的能力接上电。copilot-auth 不实现任何 GitHub 协议代码，复用 DSH 内置 pi-ai 通道，token 轮换、模型发现全归内置实现。
- 叙事线：公司账号 + Copilot 订阅就在那里，但 DSH Web 端没有登录入口（痛点）→ device flow 登录实拍（网页+设备码，全程不填 Token，SSO 友好）→ 预置路由装完即现 → 模型目录兜底填充（永不覆盖你的定制）。
- 最有技术含量的一段，值得单独一张机制卡：刷新可用模型目录的三段式设计。pi-ai 目录硬编码导致新模型（如 gemini-3.8-flash）无法解析，插件做的是数据级原子补丁（pi-ai 代码版本不动）+ diff 预览 + 二次确认 + digest 绑定防漂移 + 「只增不更新」的 trade-off（ADR 0001）。这一段能撑起整篇的技术深度。
- 合规红线：GitHub AUP 禁止批量自动化滥用，文中明确「正常强度使用」；不要用「白嫖配额」类表述，强调 base 模型不耗 premium requests 的官方规则。

### 第 5 篇 · skip-browser-auth《安全地拆掉一道安全检查》

- 立意：技术深度收尾篇，标题即观点。跳过认证不等于裸奔，这篇写的就是「如何工程化地删掉一个安全层」：版本白名单、双锚点探针（runtime 本体 + 官方 connection 包）、双分支版本确认（pnpm 路径段/manifest）、fail-closed 自动休眠、运行前 backstop 复核、逐字警告输出。
- 叙事线：每次启动都要把 URL 里那串随机 token 抄进浏览器（痛点，人人共鸣）→ 自用可信网络机器的真实需求 → 但删安全检查的正确姿势是什么（本文核心）→ 行为矩阵表（哪些版本激活、哪些休眠）→ 卸载即完全恢复官方行为。
- 合规与安全表述：文首文末都要明确「仅限本机/可信网络，勿暴露 DSH 端口给不可信网络」。这篇在公众号上有被平台或读者误读为「破解/去安全化」的风险，主动把安全设计讲透是最好的防御。
- 收尾全家福：最后一篇文末放系列终章图，一张图装下五件套 + 一条龙演示：装好 dsh-m 之后，其余四个都在市场里一键安装（截图里已全部「已安装」）。这个系列本身就是 dsh-m 收录清单的活广告。

## 三、贯穿全系列的三个固定设计

### 1. 机制卡（每篇一张）

五个插件恰好演示了 DSH 插件系统的五种扩展点，技术读者会追着看：

| 期 | 扩展机制 |
|---|---|
| 1 | Web 插件 + agent 工具注册（dshm_*）+ CLI 三位一体 |
| 2 | 侧栏 footer action 入口 + 官方主题服务 + URL 参数 |
| 3 | 服务化扩展点（registerTab / registerFileViewer，对等开放） |
| 4 | cordis.patch.yml 三段 patch：挂载内置服务 + 本地路由 + settings 预置 |
| 5 | patch 替换 + 组合期版本探针 + fail-closed |

系列做完，五张机制卡拼起来就是一张「DSH 插件系统扩展点地图」，可以单独成为一篇番外或一张长图。

### 2. 提示词安装法（每篇一块可复制代码）

每个 README 都有「把整段贴给 agent 即可完成安装」的提示词块。这是 DSH 生态独有的传播梗：安装这件事本身也交给 agent，和公众号读者「AI 编程」人群高度契合，而且这段提示词天然适合被转发。每篇固定放一块，视觉上做成「复制给 agent」样式的卡片。

### 3. 真实截图优先

系列最大资产是你手上的真机实拍（市场面板、五款皮肤、工作台、device flow 登录页），全部用真实截图，设计只负责统一模板：封面卡带系列名+期数角标，正文卡统一配色与页脚。dsh-skins 的五套配色本身就是系列视觉的灵感库，封面配色可以每期跟随当期插件主题（第 5 篇用 skip 的冷色警示风）。

## 四、单篇卡片结构模板（贴图形态）

每篇 8-10 张：

1. 封面卡：系列名 + 期数 + 当期插件一句话
2. 痛点场景卡：真实使用中的不爽，一句大字 + 场景截图
3. 是什么卡：一句话定义 + 边界（不做什么和做什么同样重要）
4. 实操截图卡 × 2-3：核心功能实拍，标注箭头只留一个视觉焦点
5. 机制卡：本期用了哪个扩展点（固定栏目）
6. 设计决策卡：1 卡只讲 1 个 trade-off（fail closed、永不覆盖、只增不更新、自动休眠）
7. 安装卡：提示词安装法代码块
8. 预告卡：下一期一句话 + 系列地图

文字密度：每卡不超过 60 字正文 + 1 个视觉主体。图内文字用「结论句」不用「说明段」。
