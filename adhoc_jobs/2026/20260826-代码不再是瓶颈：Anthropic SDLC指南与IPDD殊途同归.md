# 代码已经不是瓶颈了：Anthropic 官方指南与我们的 IPDD，殊途同归

8 月 21 日，Anthropic 应用 AI 团队——专门帮企业落地 Claude Code 的那批人——发布了一份完整的实践指南：The AI-Native SDLC Playbook。

读完的第一反应不是「学到了新东西」，而是一种熟悉感：**这份指南描述的路线，和我们从 Plan First 到 SDD 再到 IPDD 走过的路，几乎是同一条。**

区别在于，它在这条路上往前多修了几站——修到了测试、部署和运维。

## 01｜官方盖章：瓶颈已经换了位置

指南开篇的判断很直接：传统 SDLC 是为「写代码最耗时、最贵」的时代设计的。PRD、估点、评审、签批，都是为了对齐一场数周到数月的开发。而现在构建被压缩到小时级，**瓶颈没有消失，只是从写代码，搬到了代码周围的一切**——规划、评审、部署，这些以人类速度运行的环节。

流程变成了一只沙漏：中间快，两头慢。交付周期，取决于跑得最慢的那段人类环节。

这个判断我们并不陌生。上一篇算 Token 账单时已经看到：AI 的成本大头根本不在「写」，而在人机之间反复搬运上下文的「读」。写代码本身越来越便宜，贵的是代码周围的一切——账单如此，流程也如此。

指南给出的解法，一句话就能说完：

**每个阶段结束时，产出一个提交进 git 的文件；下一个阶段，从读这个文件开始。**

intent.md（意图）→ spec.md（规格）→ plan.md（计划）→ 代码与测试 → 带评审记录的 PR → 线上事故诊断 → 写回新的 intent.md。一条产物链，循环闭合。

## 02｜对照：这条链，我们已经在走

把这条链和我们的 IPDD 三步对照，几乎逐段对得上：

| Anthropic 产物链 | 我们的 IPDD 实践 |
| --- | --- |
| intent.md：发起人直接和 Claude 聊出意图文件 | 意图锚定：/grill-with-docs 对抗追问，沉淀 CONTEXT.md / ADR |
| spec.md + plan.md：一次会话出规格，Plan 模式出计划，人质询后锁定 | /writing-plans 生成实施计划，独立顾问 Agent 对抗评审后锁死 |
| 多层 Agent 评审，人只审「重要」项 | 干净会话执行，顾问 Agent 多点审查闭环 |
| CLAUDE.md + Skills：组织知识版本化 | ob-harness 的 know-how 机制、错题本 |

几个细节值得单独说。

**intent.md 要求用发起人自己的语言写。**指南里的例子是保险公司的理赔运营：客服 1/3 的通话耗在纯状态查询上，想在门户做个自助查询页。这份文件既是给产品负责人审批的文档，又是下游所有 Agent 会话的输入。**需求第一次同时做到了「人能看懂」和「机器能执行」**——这正是 CONTEXT.md 在做的事，官方把它命名并标准化了。

**计划的标准是「一个新人仅凭计划就能实现」。**Plan 模式下 Claude 只能读代码、不能改，计划打磨到位、人批准之后，才放手实现。执行中偏离计划，plan.md 必须和代码在同一个 commit 里更新。这就是我们「对抗性审查通过后锁死计划」的官方版本——同一个信仰：**动手前，必须确立计划。**

**治理红线：写代码的 Agent，不能批准自己的代码。**人类通过分支保护做最终审批。判断力集中在门禁上——和我们说的「把裁决枢纽握在开发者手里」，是同一句话的两种说法。

## 03｜它走得比我们远的三站

对照之下，真正让我坐直身体的，是三件我们还没做、或没做够的事。

**第一站：Evals——每个生产事故，变成一条永久的回归测试。**

指南要求收集 20–50 个真实任务做成 eval 套件，凡是 Agent 配置变更——换模型、改 prompt、更新 CLAUDE.md、Skills、Hooks——必须先过 eval 门禁。更狠的一条：生产环境每出一个事故，就固化一条 eval。**同一个坑，只允许掉一次。**

我们的错题本机制做的是「Agent 踩的坑变成 know-how」，靠人工沉淀。官方答案是把它做成 CI 门禁，自动化、强制化。经验复利这件事，从「手动记账」到「自动复利」，中间差的就是这套 eval。

**第二站：Hooks——不商量，直接挡。**

受保护路径不许编辑、密钥不许进 diff、没有具名的发布授权，含 production 的部署命令直接被脚本挡下。不是在提示词里「劝」AI 别干，是用确定性代码让它干不了。我们说过约束要越做越薄——现在看明白了：薄的是提示词约束，厚的是工程护栏。这才是「薄」的正确形态。

**第三站：维护闭环——事故诊断写回 intent.md。**

确定性脚本监控控制带：1σ 只记录，2σ Claude 只读诊断，3σ 可以提 PR、触发预批准的回滚手册。诊断结果不是发条告警就完，而是写成一份新的 intent.md，进入分诊队列。

**维护的输出，变成了新需求的输入。**这是整份指南里最有想象力的一步：生产环境的每一次疼痛，自动变成下一轮开发的第一个文件。循环，就此闭合。

## 04｜明天就能做的三件事

指南是模块化的，规划阶段没有任何前置依赖，从哪里开始都行。按我们自己的实践节奏，建议从这三件做起：

**1. 给仓库写 CLAUDE.md。**四节就够：常用命令、团队约定、架构地图、AI 容易犯的错。这就是错题本的官方形态，一次性投入，从下一个会话开始复利。

**2. 把「完成」定义成一条命令。**写进 CLAUDE.md：报告任务完成前，跑构建、测试、lint 三项并贴出输出；测试失败，修代码，不修测试。从此你审的不再是「AI 说它做完了」，而是三项检查的原始输出。

**3. 核心任务，从 plan.md 开始。**这正是 IPDD 的第二步。Anthropic 给的验收标准可以直接抄：一个新人，仅凭这份计划就能实现。

## 结语

这份指南表面讲流程，实际讲的是一次价值转移：**当写代码的价格趋近于零，软件工程里贵的东西只剩下三样——说清楚要什么（意图），定义什么算好（标准），判断什么能上（责任）。**

我们在 IPDD 的结语里写过：把机械的执行链条托付给模型生态，把裁决枢纽握在开发者自己手中。这一次，Anthropic 用两句更短的话说了同一件事：

**循环持续运转。人类的判断力，应始终在它之上。**
