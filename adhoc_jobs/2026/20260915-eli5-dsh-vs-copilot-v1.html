DeepSeek Harness vs GitHub Copilot

两者都是给模型（发动机）套上 harness（底盘、方向盘、门锁），但车停进了不同的车库：Copilot 把 AI 住进你的编辑器，DSH 让你坐在浏览器里、远程指挥一台属于它的机器。记住这个镜像关系，后面每一屏都是它的一个切面。

切面一 · 宿主：插件插槽 vs 一台整机

Copilot 住在你 IDE 的插件插槽里，像装在车上的导航仪——拔下来，车照开。DSH 本身是一个自托管服务（systemd 守护进程 ＋ 浏览器入口），像雇了位代驾——他开他自己的车，你只负责指路。

切面二 · 工作单元：一次建议 vs 一张行程单

Copilot 的基本单位是「一次建议」——补全、一个 diff（一页修订稿），等你按 Tab 定夺。DSH 的基本单位是「一个任务」：后台跑的脚本、一支并行小队，甚至一张跨天续跑的行程单（goal）。

切面三 · 权限：逐扇门签字 vs 分级门禁卡

Copilot 默认逐个动作向你确认，像每开一扇门都找你签字。DSH 用分层门禁：外层沙箱圈死活动范围，中层策略决定哪些动作必须审批，真要越界就一次性申请提权——并强制附带一句理由。

切面四 · 记忆：屏幕便签 vs 三层员工手册

Copilot 靠指令文件和聊天上下文记事，像贴在屏幕边的便签。DSH 把上下文做成三层：常驻规则每轮必读、技能目录按需翻全文、插件装进来自带说明书——该在的都在，不该来的不占地方。

切面五 · 编排：一个助理 vs 一位能拉群的经理

你和 Copilot 的对话基本是单线程的；平台侧的 coding agent 能把 issue 变成 PR，但它不在你的编辑器里。DSH 的主智能体可以随手拉群：派子智能体、用一段脚本当排班表并行跑、后台任务不断线——你合上笔记本它还在干。

切面六 · 生态：装 app vs 改水电

Copilot 的扩展从市场装进 IDE，外部工具靠 MCP 转接头接入——能力住在编辑器里。DSH 的插件直接装进 runtime 本体，技能是一页页随取随用的说明书——装完之后，「房子本身」多了新的水电线路。

收尾 · 回到全景：一张表复述全程

顺着表格从上到下读一遍，你就能向同事复述两者的差别：Copilot 把 AI 带到你的工位，DSH 把你的工位搬到 AI 面前。这不是优劣题，是位置题——先想清楚活儿该在谁的地盘干，再挑工具。
