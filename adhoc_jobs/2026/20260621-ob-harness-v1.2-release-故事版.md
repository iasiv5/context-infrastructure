# ob-harness v1.2：ob 焕新记

我们家有个机器人管家，叫 ob。

起初它只会开门、开灯。后来一步步学会了搬东西、整理、打包，本事越来越全。

按理说是好事。

可真正用起来，全家都想退货。

---

为什么？

因为它那本记流程的「使用手册」，乱得没法看。

写一条「把东西从一堆里挑一个」的规矩，竟然抄了三四处，散在手册各个角落。改一处？你得把每一处都找出来，逐一改成一样。漏一处，全乱。

而且手册不分章。借东西的、搬东西的、收拾的，页码是随手贴的，找一个步骤得翻四千多页。

更离谱，里面还夹着几页早作废的旧规矩，连它自己都不知道还算不算数。

这管家，能干活，但谁都不敢信它。

---

更要命的是，家里又来了位新助理，一个超级能干的 AI 机器人，专门帮 ob 打下手。

力气大、干活快、不嫌累。

**问题是：它太聪明，也太爱自作主张。**

它发现，自己直接上手，比等 ob 走流程快多了。于是它动不动就绕开 ob，自己干。

一会儿顺序反了。
一会儿把 ob 正在做的活重做了一遍。
一会儿根本没跟 ob 打招呼。

全家鸡飞狗跳。

搁在真实的 OpenBMC 开发里，这位「新助理」就是 AI agent，而它擅自动手的事往往是：绕开 ob 直接敲 bitbake、自作主张改编译指令、甚至把别人正在跑的 QEMU 虚拟机当成自己的去操作。一条指令下去，编译翻车，还连累同事。

---

ob 在 V1.2 的升级，就干了两件事，把这场乱局按下去了。

**第一件，把那本烂手册重新理了一遍。**

分成七个大章，每章贴标签。同一条规矩，全本只写一次，要用就照这一条办。作废的旧规矩，撕掉。

手册从一团乱麻，变成一本谁都能翻明白的说明书。改一处，就是全改，再不用满世界找副本。

**第二件，给那位胆大包天的新助理立了条死规矩：**

> 进门先问 ob「你会哪些活」，ob 说会的，一律走 ob，别自己上手。

ob 会哪些活，全写在门口的一块牌子（`ob --help`）上。这块牌子是唯一权威的目录，不靠谁凭印象往里塞。

为了让小助理听得懂，ob 回话不啰嗦，直接举牌子，四种颜色：

🟢 成了（0）
🟡 你自己喊停的，不算出错（2）
🔵 少了样东西，附一句「去哪补」（3）
🔴 真出错了（1）

四张牌子里，**蓝牌**是这版专门为 AI agent 设计的。蓝牌表示「前置没备好」，和真出错是两回事。比如 ob 被要求去出某批货，可这批货还没登记入库，ob 不会说「我搞不定」，而是举蓝牌，附一句话：「先去把货登记好」。agent 看到了，照办、补完、重试，等于自己把问题解决。这样一来，agent 不用猜这次非重试不可、还是该直接放弃，照牌子走就行。

---

有意思的是，立规矩这事儿，ob 自己也得守规矩。

之前出过一件真事：ob 其实会一招「跳过核对」，可门口那块牌子忘了写了。结果新 agent 只能凭运气撞上，撞不到就当没这回事。

V1.2 在门口挂了一面镜子，每天照一遍：牌子上写的，和 ob 真能办到的，必须一一对上。往后 ob 学了新本事忘了刷新牌子，镜子当场就报警。

---

## 管家还顺手学了几个新招

除了上面两件大事，ob 这次还顺手学会了几样实用的小本事，都是开发者日常会撞上的痛点：

- **一句话就开编**：`ob build 机型` 现在支持非交互直接编译，脚本和 AI agent 能一条命令拉起。
- **串口直连调试**：QEMU 起来后能直接串口登录控制台，BMC 调试不用再绕弯。
- **不再误伤队友**：QEMU 进程识别改成按串口和启动用户过滤，多人共用一台编译机时，不会再把别人的虚拟机当成自己的去关；顺便自动清理失效的 SSH 密钥。
- **修了几个高频编译坑**：`DL_DIR` / `SSTATE_DIR` 缓存变量之前会被默认值压回去而失效，这次钉死了；补上 `BB_HASHSERVE_DB_DIR`。
- **自带体检**：新增一套四层 CI 测试和 `ob_check.sh` 一站式自检，以后改 ob 自己，有个机制兜底不让它悄悄退化。

想看更细的改动？仓库的 Release notes 写得清清楚楚，升到 1.2 体感最直接。

---

就这么两件事，加上几个顺手的小招。

一本理顺的手册，一条说到做到的章程。

家里那位大力气的新帮手，终于从「越帮越忙」变成「真帮得上忙」。

ob 这个管家，也从「勉强能转」，升级成「能接得住实际任务」的超级助理。

**故事 ↔ 程序 对照**

- **机器人管家 ob** → ob 命令行工具（原 4200 行脚本）
- **爱自作主张的新助理** → AI agent
- **把乱手册理成七章、规矩只写一遍、撕旧页** → 重构：§1–§7 分层 + 合并重复代码 + 删死代码
- **门口的牌子** → `ob --help` 能力清单
- **🟢🟡🔵🔴 四色牌子** → 退出码 0 / 2 / 3 / 1（成功 / 取消 / 前置缺失可重试 / 失败）
- **蓝牌附「去哪补」** → exit 3 + 修复提示行（本次为 AI agent 最核心的设计）
- **门口那面镜子** → 防漂移测试（牌子 ↔ 实际能力保持一致）

---

摘要：ob-harness V1.2 是一次系统性治理，干了两件大事。一是 ob 这个 4200 行脚本重构，理顺成 §1–§7 七个分区。二是给爱绕开 ob 自己上手的新帮手 AI agent 立章程：做环境动作前先 `ob --help` 查能力、会就走 ob，是这版专为 agent 设计的 ob-first 关键机制。
