# IPDD：是时候放弃重度 Agentic Workflow 了

自 2025 年 9 月探索 Agentic Workflow 以来，我们的 **AI 编程工作流**经历了三次大重构。每次演变的核心驱动力，都是在模型能力变强与调度框架升级后，重新寻找一个平衡点：动手写代码前，到底需要给 AI 套上多少约束？

## 阶段一：Plan First，先规划再执行

早期我们重度依赖各类工具的 Plan Mode。标准流程是：输入目标，由 Agent 列出对应的动作规划，开发者确认无误后再切换至执行模式。

此时的事前规划负担很重。因为模型单次输出高质量代码的成功率偏低，人必须事无巨细地指挥 AI 的每一步操作。Plan Mode 虽然终结了聊天框里的无休止对话，清晰划定了代码边界，但依然无法兜底最终的交付质量。

## 阶段二：SDD（规范驱动开发），沉重但必需的基建

当 Plan Mode 无法兜底严肃固件编程的质量时，我们引入了 GSD、OpenSpec 等开源 SDD 框架（Spec Driven Development）。这要求 Agent 强制对齐业界模板，输出需求分析（proposal.md）、增量规范（specs.md）、技术设计（design.md）与实现清单（tasks.md），并全部落盘为实体文档。

这套策略带来了极高的流程成本。哪怕只加一个接口，也得跑完这套全量文档落地流程。尽管在团队普遍缺乏 AI 工程素养的阵痛期，这种重资产模式不可或缺，但高昂的推广与维护成本也引发了**巨大的内部阻力**。

## 阶段三：IPDD（实施计划驱动开发），回归实用主义

进入 2026 年中，GPT-5.4 与 Opus-4.6 等强力模型相继发布。百万级 Token 上下文与更强的注意力机制，让模型直接内化了工程结构素养。针对一般性开发任务，Agent 已经能精准拆解动作，并在长程执行中不偏离路线。我们据此演进出 IPDD（Implementation-Plan Driven Development）模式。

在 IPDD 模式下，仅靠一份清晰的实施计划，就足以驱动 Agent 全自主闭环任务。

对比流程产物，变化显而易见：
*   **SDD 阶段：** 规划环节串行生成四五份厚重的领域文档，再通过 apply、verify、archive 等指令反复交叉执行与验收。
*   **IPDD 阶段：** 前置流程极度压缩。AI 只需输出一份实施计划作为执行大纲。对抗性审查通过后，Agent 即可单刀直入、快速推进。

### 真金白银的倒逼：被 Token 成本逼出的分轨制

除了模型本身的进化，商业策略变更也倒逼了 IPDD 的全面落地。

2026 年 6 月，GitHub Copilot 将 Enterprise 套餐从按请求次数计费改为按量消耗（Usage-based Billing）。Token 额度的大幅收紧，迫使我们在日常开发中对任务严格分层：

1. **轻量任务直接发指令。** 替换 Logo、分析函数调用链或格式化代码等微小改动，剥离一切流程牵绊，在当前会话直出结果。
2. **核心任务强切 IPDD。** 涉及跨文件接口拆分或核心逻辑改造，强制走完 IPDD 流程。事前锁死路径细节，杜绝 Agent 重试和返工，浪费宝贵 Token。

### IPDD 标准三步走

应对需要完整 IPDD 支持的攻坚任务，我们沉淀出如下解决路径：

📍 **1. 意图锚定与对齐**
调用带领域建模与对抗追问机制的 agent skill（如 `/grill-with-docs`）。面对模糊诉求主动发问，死磕逻辑盲区与任务边界条件。将提取出的领域知识、决策背景统一沉淀至 CONTEXT.md 或 ADR 中，拉齐人机认知。

📝 **2. 实施计划生成与锁定**
基于锚定的前置意图，调用 `/writing-plans` 自动生成切分合理、上下文闭环的实现草案。将草案转交独立顾问 Agent 进行对立评审，排查边界漏洞，经过多轮PK，无异议后锁死计划细节。

✅ **3. 最终执行与验收**
新开一个干净的会话窗口（避免旧上下文污染），授权主力 Agent 依计划修改基线代码。产出完成后再次激活顾问 Agent，对交付的代码堆栈和附属文档执行多点审查，形成闭环。

---

## 结语

纵观三次工作流更迭，前置的重度约束随着模型升维而不断消退。我们将越来越多的繁杂细节放手交给 Agent 全自动处理，但始终坚守着一条底线：动手前，必须确立计划。

**厚重的工程文档，正在向纯粹的实施计划回归**。我们把机械的执行链条尽数托付给大模型生态，把最重要的裁决枢纽——也就是判断与定夺的权力，稳稳地握在开发者自己手中。

***
*摘要：从重度依赖人工规划的 Plan First，到追求严苛文档落地的 SDD，我们的 AI 编程实践最终走向了聚焦业务实施的 IPDD。2026 年中 Token 计费策略的变更，进一步催化了轻重任务的分流体系。这一场长达数年的演进，核心只为做成一件事：依托模型渐进内化的工程能力，把繁重的代码产出任务从人身上剥离，将核心决断权做到极致聚焦。*

*摘要 ：AI编程实践历经 Plan First、SDD，最终走向 IPDD。在 Token 计费变更的催化下，我们建立轻重任务分流。数年演进只为一件事：用AI剥离繁长编码，让人类极致聚焦核心决断。*
