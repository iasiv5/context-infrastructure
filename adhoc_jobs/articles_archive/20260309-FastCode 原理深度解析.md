# FastCode 原理深度解析

## 📚 整体架构：三阶段框架

FastCode 使用了一个革命性的 **"侦察先行"（Scouting-First）** 框架，完全不同于传统的代码理解方法。

### 传统方法 vs FastCode

**传统方法（Cursor/Claude Code）❌**
```
问题 → 加载文件 → 搜索 → 加载更多文件 → 再搜索... → 答案
💸 重复加载文件，Token 浪费严重
```

**FastCode 方法 ✅**
```
问题 → 建立语义地图 → 结构导航 → 精准加载 → 答案
💰 只加载需要的代码，最小化 Token 消耗
```

---

## 🏗️ 核心技术组件剖析

### 1️⃣ 代码解析器（CodeParser）- 理解代码结构

FastCode 的核心优势在于它不是简单地"阅读代码"，而是先建立代码的"智能地图"。

#### 多层级代码单元提取

FastCode 将代码分解为 4 个层级：

```python
CodeElement {
    type: "file" | "class" | "function" | "documentation"
    name: "User.authenticate"
    code: "def authenticate(): ..."
    signature: "authenticate(username, password) -> bool"
    docstring: "验证用户身份"
    embeddings: [0.23, -0.45, ...]  # 语义向量
    metadata: {
        file_path: "auth.py",
        start_line: 42,
        end_line: 67,
        complexity: 8,
        imports: ["from database import DB"]
    }
}
```

**为什么这很重要？**
- 传统方法：需要把整个 `auth.py` 文件（可能 1000+ 行）发给 LLM
- FastCode：只发送 `authenticate` 函数的定义和签名（50 行），节省 **95% 的 Token**

#### 支持的编程语言

FastCode 使用 **tree-sitter** 和 **libcst** 进行 AST 解析，支持：
- 🐍 Python
- 📜 JavaScript / TypeScript
- ☕ Java
- 🦀 Rust
- 🐹 Go
- ⚙️ C / C++
- 💎 C#

### 2️⃣ 语义嵌入向量化

#### 语义嵌入向量化

FastCode 使用 **Sentence Transformers** 模型将代码转换为数学向量：

```python
# 代码文本
"def authenticate_user(username, password):"

# 转换为 384 维向量
[0.234, -0.567, 0.891, ..., 0.123]  # 384 个数字

# 这些向量捕捉了语义相似性：
# - "verify_login" 和 "authenticate" 距离很近
# - "send_email" 和 "authenticate" 距离很远
```

**关键技术点：**
- 使用 **paraphrase-multilingual-MiniLM-L12-v2** 模型
- 支持多语言（中文、英文、代码混合）
- 只有 470MB，可以在本地运行

**向量搜索性能：**
- 使用 **FAISS** 向量数据库
- 支持近似最近邻搜索（ANN）
- HNSW 索引，毫秒级响应

### 3️⃣ 三层关系图构建

FastCode 构建三种图来理解代码之间的关系：

#### 调用图（Call Graph）- 谁调用了谁

```python
authenticate → verify_password → get_user_from_db
     ↓              ↓
  log_attempt   update_last_login
```

**应用场景：**
- 理解代码执行流程
- 影响分析（修改函数会影响哪些调用方）
- 重构安全检查

#### 依赖图（Dependency Graph）- 文件级依赖

```python
auth.py ──imports──> database.py
  │                    │
  └──imports──> utils.py
```

**应用场景：**
- 模块化分析
- 循环依赖检测
- 构建优化

#### 继承图（Inheritance Graph）- 类继承关系

```python
AdminUser ──extends──> User
    │                    │
SuperAdmin ──extends──> AdminUser
```

**应用场景：**
- 面向对象设计分析
- 多态调用点查找
- 重构影响评估

**为什么需要图？**

当用户问"如果我修改 User 类会怎样？"，FastCode 可以：
1. 在继承图中找到 `AdminUser`、`SuperAdmin`
2. 在调用图中找到所有调用 `User` 方法的代码
3. 精准返回受影响的 10 个文件，而不是盲目搜索整个仓库

### 4️⃣ 智能检索（HybridRetriever）

#### 两阶段智能搜索

**第一阶段：粗筛**

```python
# 用户问题："如何处理用户登录？"

# 1. 语义搜索
query_embedding = embed("如何处理用户登录")
# 找到相似度 > 0.3 的代码片段
results_semantic = [
    ("authenticate", 0.89),  # 高度相关
    ("verify_password", 0.75),
    ("logout", 0.45),
    ...  # 共 50 个候选
]

# 2. 关键词搜索（BM25）
results_keyword = bm25_search("login", "auth", "user")
# 返回包含这些关键词的代码

# 3. 图遍历（扩大召回）
# 从 authenticate 开始，遍历调用图 2 步
graph_results = traverse_graph(
    start="authenticate",
    depth=2  # authenticate → verify_password → get_user
)
```

**第二阶段：精排和过滤**

```python
# 合并三种搜索结果，重新打分
final_results = rerank(
    semantic_results,
    keyword_results,
    graph_results,
    weights=[0.5, 0.3, 0.2]  # 可配置权重
)

# 只返回 top-5 最相关的代码片段
# 每个片段包含：
# - 函数签名（不包含完整实现）
# - 相关的类定义
# - 依赖的导入
# - 调用上下文
```

**为什么这比传统方法好？**
- 传统方法：搜索 → 加载 100 个完整文件 → LLM 理解 → 返回答案
- FastCode：搜索 → 加载 100 个函数签名 → LLM 理解 → 按需加载 5 个函数的完整代码

### 5️⃣ 迭代代理（IterativeAgent）- 核心创新！

这是 FastCode 最大的创新点！一个**会"思考"的智能代理**。

#### 迭代代理的工作流程

```python
# 用户问题："这个项目的支付流程是如何实现的？"

# === 第 1 轮：初步评估 ===
Agent思考："我需要先了解项目结构"
工具调用：
  ✓ list_directory(".")  # 查看根目录
  ✓ search_files(["payment", "checkout", "order"])  # 搜索相关文件

发现：
  - src/payment/processor.py
  - src/api/checkout.py
  - src/models/order.py

置信度：40% → "需要更多信息"

# === 第 2 轮：深入探索 ===
Agent思考："让我看看 payment/processor.py 的结构"
工具调用：
  ✓ read_file_signatures("src/payment/processor.py")  # 只读函数签名！
  ✓ get_call_graph("PaymentProcessor")  # 查看调用关系

发现：
  - PaymentProcessor.charge() → StripeAPI.call()
  - PaymentProcessor.refund() → StripeAPI.refund()

置信度：65% → "理解了核心逻辑，但需要细节"

# === 第 3 轮：精准获取 ===
Agent思考："让我看看具体的实现细节"
工具调用：
  ✓ read_function("PaymentProcessor.charge")  # 只读这个函数！
  ✓ read_function("StripeAPI.call")

置信度：92% → "已经理解支付流程"

# === 第 4 轮：置信度检查 ===
Agent思考："置信度 > 95%，可以停止检索"
决策：停止，生成答案

# === 最终答案 ===
总结：
"这个项目使用 Stripe 处理支付：
1. 用户通过 API 发起支付 → src/api/checkout.py
2. PaymentProcessor 调用 Stripe API → src/payment/processor.py:42-67
3. 订单状态更新 → src/models/order.py:89-104
共涉及 3 个文件，200 行代码"
```

**关键技术点：**
- **自适应迭代**：简单问题 2 轮，复杂问题 4-5 轮
- **置信度控制**：达到 95% 置信度自动停止
- **按需加载**：只读取需要的函数，不是整个文件
- **成本意识**：每轮都会计算"信息增益"，决定是否继续

#### 智能工具集（AgentTools）

```python
class AgentTools:
    """只读工具，确保安全"""

    def list_directory(path)       # 列出目录内容
    def search_files(keywords)     # 搜索文件
    def read_file_signatures(path) # 只读函数签名（不读完整代码）
    def read_function(name)        # 读取单个函数
    def get_call_graph(func)       # 获取调用关系
    def get_dependencies(file)     # 获取依赖关系
    def file_path_to_module(path)  # 路径转模块名
```

**安全机制：**
- 只读操作，不修改代码
- 安全边界检查，不能访问仓库外部
- 操作日志记录，可追溯

## 🎯 实际案例演示

**问题**："如果我要修改 User 模型的 password 字段，会影响哪些代码？"

### Cursor/Claude Code 的做法：
```
1. 搜索 "password" → 返回 1000 个结果
2. 读取 100 个包含 "password" 的文件
3. LLM 分析所有文件
4. 返回答案

Token: ~80,000
时间: ~25 秒
```

### FastCode 的做法：
```
1. 查询依赖图：找到所有依赖 User 模型的代码
   结果：5 个文件（auth.py, views.py, serializers.py, ...）

2. 语义搜索："password field modification"
   结果：auth.py:89 (User.set_password)
         views.py:45 (login_view)
         serializers.py:23 (UserSerializer)

3. 调用图遍历：从 User 模型开始
   User.set_password → called by auth.py, views.py
   User.check_password → called by auth.py

4. 精准读取：只读 5 个相关函数
   - auth.py:89-105 (set_password)
   - auth.py:107-120 (check_password)
   - views.py:40-60 (login_view)
   - serializers.py:20-35 (UserSerializer)
   - tests/auth_test.py:15-30

5. 生成答案

Token: ~8,000
时间: ~3 秒
```

**结果：FastCode 使用了 10 倍少的 Token，快了 8 倍！**
