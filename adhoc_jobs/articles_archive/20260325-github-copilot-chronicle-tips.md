# 别把Copilot当聊天框：2个隐藏指令，让AI长出“永久记忆”

**分享摘要**：每天都在用 Copilot，但总觉得它不够懂你？今天分享两个高频隐藏指令，别再把超跑当马车赶，让 AI 真正学会你的工作流。

---

每天都在用 GitHub Copilot，但你有没有觉得，有时候换个项目或者隔了几天，它就又变成了一个“熟悉的陌生人”？每次对话都要不厌其烦地重新铺垫背景、重复强调你的常规要求。

其实，真正用好 AI 的标志，不是你每天跟它聊了多少句代码，而是**它是否在不断学习你的工作模式**。

今天给大家分享两个我在 GitHub Copilot CLI 中高频使用的隐藏指令：`/chronicle tips` 和 `/chronicle improve`。它们不仅能精准指出你给 Prompt 时的“坏习惯”，还能帮你把个人经验固化成整个代码仓库的“永久记忆”。

### 🛠️ 这俩“神仙指令”是什么？

简单来说，这两个指令是 Copilot 自带的**反思与进化机制**：
*   `/chronicle tips`：让 AI 翻阅你们最近的对话记录，分析你的提问习惯，并直接反向指导你：“其实你怎么怎么用我，效率会更高。”
*   `/chronicle improve`：把你俩之前讨论出的好约定、好做法，自动总结并写入到项目的 `copilot-instructions.md` 或 `AGENTS.md` 里，形成它的“肌肉记忆”。

---

### 💊 `/chronicle tips` 给我开的“5剂处方”

最近我跑了一次 `/chronicle tips`，不得不说，AI 挑毛病真是一针见血。结合我的日常操作，它直接给我列出了 5 条改进建议，看完直呼受用：

**1. 别问“能不能做”，直接丢终极目标**
以前我总喜欢像聊天一样先问一句：“mp4 提字幕有什么好的方法？” 等 Agent 回答了，再发具体任务。
但它建议我：想要什么直接说。比如直接下发：
> *"把 video.mp4 转成逐字稿，保留时间戳，顺便每5分钟做摘要，输出 srt 和 md。"*

大部分情况下，AI 现在的能力完全可以直接开干，没必要在那假客气。

**2. 联网调研，优先呼叫 `/research`**
当遇到“查 Docker 官方发布动态”这种又要找来源、又要总结对比的任务时，别再傻乎乎地用基础网页访问工具在那瞎转了。直接上 `/research`，能省去大量中间步骤，效率翻倍。

**3. 想控住并发，就把要求写进 Prompt**
今天下午我刚好遇到了 AI 疯狂开 subagent，导致进程差点卡死的惨剧。
AI 给我的应对策略是，在提示词开头就立规矩：*"只用单 agent、最多 1 个后台任务、除非卡住否则不要开 subagent"*。顺便配合 `/tasks` 命令盯紧后台，它就会老实很多。
*（不过说实话，这一条我暂时没听它的——在我心中，现阶段放纵 sub-agent 去疯狂试错，依然是利大于弊的。）*

**4. 拒绝“挤牙膏”，熟练切换模式**
在长线任务里，我之前的习惯是：“它改一点 -> 我说‘好的’ -> 它再改一点”。
正确的姿势是：遇到大活，先用 `/plan` 做计划，或者开 `/experimental` 后，用 `Shift+Tab` 把它切到 **Autopilot 模式**。设定好目标让它自己持续干完，不需要你像个监工一样频繁接力。

**5. 把高频操作，固化成专属 Skills**
它发现我在当前 workspace 经常做转录、OCR、联网汇总等操作，于是提醒我：别每次都重新念咒！在这个仓库里建个 `.github/skills/`，把这些做成定制化的 skill，以后一句话就能触发一套复杂的组合拳。

---

### 🧠 `/chronicle improve`：让经验变成团队资产

如果你只想做个普通的AI使用者，知道 tips 就够用了。但如果你想打造一把真正趁手的兵器，就必须用上 `/chronicle improve`。

在我的工作流里，我希望在这个仓库里，AI 永远**默认用中文回复**、**写 Python 脚本不要动辄就造复杂的工程结构**、**所有路径都给我用 Windows 兼容的反斜杠**。

每次发 prompt 都带上这些太累了。现在，只要敲入 `/chronicle improve`，它就会根据我们之前的摩擦点，自动把这些“潜规则”提炼出来，并建议你写入 `.github/copilot-instructions.md`。

这就相当于给这个项目的 AI 注入了“灵魂”。不管以后是你自己，还是团队里新来的同事在这个仓库里唤起 Copilot，它加载时的配置就会像这样：

```markdown
# Repository Copilot Instructions

- **沟通语言**：在这个仓库始终默认使用中文回复。
- **编码习惯**：寻找功能时请先看 `scripts/` 下独立的 Python 文件，基于现有脚本修改，不要过度设计（over-engineering）或重新造轮子。
- **环境预检**：在执行自动化脚本命令前，先检查系统依赖（如 `ffmpeg` 或 `playwright`）是否已安装。
- **路径规范**：所有的示例和生成路径，请默认使用符合 Windows 习惯的反斜杠（\）。
```

从此以后，它才会真正变成**你的** Copilot。

### ✍️ 总结

说实话，用好 AI 的第一步，是**戒掉把它当聊天机器人（ChatBot）用的习惯**。

真正的高手，不仅是在和 AI 一起写代码，更是在**构建工作体系**。用 `/chronicle tips` 纠正自己的交流姿势，用 `/chronicle improve` 沉淀项目规范。慢慢地你就会发现，你的 Copilot 会变得比你想象的聪明得多。
