## 术语说明：先统一这几个关键词

- GitHub Copilot：GitHub 的 AI 编程助手产品。
- Copilot Chat：Copilot 在 VS Code 中的对话式交互能力。
- agent / agent mode：代理 / 代理模式，指能分步骤执行任务的智能体能力。
- Plan agent：规划代理，先负责拆解需求和澄清问题。
- inline suggestions：行内建议，也就是常见的代码补全和幽灵文本建议。
- inline chat：行内对话，在编辑器里就地发起的精准修改请求。
- custom instructions：自定义指南（**/.github/copilot-instructions.md,AGENTS.md**），用来补充项目级或任务级上下文。
- MCP：Model Context Protocol，用于把外部工具和服务接入 Copilot。

## GitHub Copilot 是什么：从代码补全到自主协作式编程助手

GitHub Copilot 是一款 AI 编程协作工具，它正在改变开发者在 Visual Studio Code 中编写代码的方式。

官方对它的定位是“你的自主型 AI 编程搭档”。这层含义并不只是在说它会补全代码，而是在强调它已经开始具备“协作式完成任务”的能力。换句话说，Copilot 想占据的位置，已经不只是“写几行代码时顺手帮你补一下”，而是“在更完整的开发流程里和你一起推进任务”。

GitHub Copilot 的代理可以端到端处理完整的编码任务，包括自主规划工作、编辑文件、运行命令，并在遇到错误时进行自我修正。除此之外，你也可以继续使用行内建议来获得快速的编码辅助，或者通过行内对话直接在编辑器中完成更聚焦、更精准的修改。

官方同时引导新用户从 GitHub Copilot Free 方案开始体验。

## 如何获得 GitHub Copilot 使用权限

如果你想开始使用 GitHub Copilot，可以注册 GitHub Copilot Free，或者向企业管理员申请开通权限。

需要注意的是，要访问 GitHub Copilot，前提是你拥有一个有效的 GitHub Copilot 订阅。关于个人版和企业版的差异，官方建议前往 GitHub Copilot 的产品页面进一步查看。

## 用自主代理完成完整编码任务

GitHub Copilot 的一个核心方向，是让 AI 代理端到端地实现复杂功能。你只需要给代理一个高层次任务，它就会把工作拆成多个步骤，修改多个文件，运行终端命令，并在出现错误或测试失败时继续调整和修复。

按照官方描述，这类代理尤其擅长以下任务：构建新功能、调试并修复失败的测试、重构代码库，以及通过拉取请求协助团队协作。这里最值得注意的，不是它“会写代码”这件事，而是它开始具备了把多个动作串成一条执行链的能力。

你还可以在统一视图中管理多个代理会话。多个代理会话可以并行运行，并被集中追踪在一个位置。你可以查看会话状态、切换当前正在进行的工作、审阅文件变更，并在中断后继续之前的任务。

在运行形态上，Copilot 代理并不只局限于 VS Code 本地。你可以在 VS Code 中本地运行代理，也可以通过 Copilot CLI 在后台运行，或者使用云端的 Copilot Coding Agent。官方还提到，你可以和 Claude、Codex 等不同提供方配合使用，并在不同代理类型之间交接任务，同时保留上下文。

这意味着，Copilot 正在把“一个编辑器里的辅助能力”往“跨环境持续工作的执行系统”方向推进。

> 译者注：本文中的“代理”更接近“能围绕目标持续执行多步任务的 AI 执行体”，而不只是一个会回答问题的聊天窗口。

## 先规划，再执行：Plan Agent 的作用边界

在正式动手编码之前，你还可以先使用 Plan agent 来完成规划。这个规划代理会把任务拆解成结构化的实施计划，并在必要时主动提出澄清问题。

当计划准备完成后，再把它交给执行型代理去真正落地。官方也提到，你还可以把任务委托给云端代理，让它们创建分支、实现修改，并打开拉取请求，供团队进一步审查。

这一段隐含的重点是：GitHub Copilot 不再只提供“写代码”这一个动作，而是在尝试覆盖“先分析、后执行、再协作审查”的完整链路。对很多开发者来说，这也是理解 Copilot 新阶段能力边界的关键转折点。

## 除了 Agent，你还可以怎样与 Copilot 协作

除了代理模式，Copilot 还提供多种更轻量的 AI 协作方式。

当你在编辑器里输入代码时，Copilot 会提供智能的行内建议，包括幽灵文本建议和“下一步编辑建议”，帮助你更快完成编码。Copilot 会预测你接下来最可能进行的修改，而你可以通过 Tab 键直接接受这些建议。

原文在这里同样配有一段示意视频，用来展示 Copilot 的下一步编辑建议能力。

如果你希望做更聚焦的局部修改，可以使用行内对话。只要按下 Ctrl+I 或 Cmd+I，就可以直接在编辑器中打开对话输入框。你描述一次修改意图后，Copilot 会就地给出编辑建议，例如重构方法、补充错误处理，或者解释复杂算法，而无需离开当前编辑上下文。

这也是原文想强调的一点：Copilot 并不是只有“开一个大面板对话”这一种用法，它同时覆盖了补全、局部编辑和多步骤代理执行等不同层级的交互入口。你可以把它理解为一套分层协作体系，而不是一个单一功能按钮。

## 如何让 Copilot 更懂你的项目和工作流

官方明确指出，代理只有在理解项目约定并拿到合适工具时，效果才会最好。因此，你可以对 Copilot 做定制，让它从一开始就更贴合你的代码库。

第一层是项目上下文。你可以通过自定义指令，为 Copilot 提供项目级或任务级的背景信息、编码规范和约束条件。

第二层是能力扩展。你可以用 agent skills 为 Copilot 教授更专门的能力，也可以通过自定义代理定义出更有针对性的角色人格。

第三层是外部工具接入。通过 MCP 服务器和扩展，Copilot 可以连接外部数据源、API 或其他专用工具，从而获得更强的上下文和执行能力。

如果说前两层解决的是“它是否更懂你”，那么这一层开始解决的就是“它是否能真正接触到完成任务所需的外部能力”。

> 译者注：这一节其实对应三层能力增强路径，分别是“告诉它项目规则”“给它专门能力”“让它接入外部工具”。理解这三层关系，比记住单个术语更重要。

## 支持的语言与框架

GitHub Copilot 支持几乎所有主流编程语言，包括 Java、PHP、Python、JavaScript、Ruby、Go、C# 和 C++。由于它基于公开代码仓库中的多语言数据进行训练，因此对大多数常见语言、库和框架都具备适配能力。

## 版本兼容：为什么最新版 VS Code 很重要

由于 Copilot Chat 与 VS Code 的界面集成非常深，二者的发布节奏是紧密同步的。也正因此，每一个新的 Copilot Chat 版本，只会兼容最新版的 VS Code。

这意味着，如果你仍在使用较旧版本的 VS Code，就无法获得最新的 Copilot Chat 功能。

官方还特别提醒，只有最新版本的 Copilot Chat，才会使用 Copilot 服务侧提供的最新模型。因为哪怕只是模型的细微升级，也往往需要扩展侧同步调整提示词和修复兼容性问题。

这也是为什么很多“我明明装了 Copilot，为什么看不到最新能力”的问题，最后都会回到版本兼容这一层。

## 隐私、预览条款与安全更新说明

当你使用 Copilot Chat 时，意味着你同意 GitHub Copilot Chat 的预览条款。官方建议用户同时阅读透明度说明，以了解这一技术预览阶段的使用方式、能力边界与改进路径。

官方也强调：“你的代码属于你自己。” GitHub 表示会依据其隐私声明采取负责任的做法，确保你的代码片段不会被作为其他用户的建议代码直接复用。

如果你希望及时获得最新的安全修复，官方建议始终使用最新版的 Copilot 扩展和 VS Code。
