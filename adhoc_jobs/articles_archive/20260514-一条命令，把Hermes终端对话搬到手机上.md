# Hermes Agent /handoff 命令详解：CLI 会话无缝转交飞书

你正坐在电脑前用终端跑 Hermes Agent，让它帮你改一个棘手的 Python 爬虫。它刚读完报错日志，分析到一半——手机响了，你必须马上出门。

以前怎么选？拍张截图发给自己，到地铁上掏出飞书把前因后果重新说一遍？还是合上电脑，等回来再继续？

不管怎么选，**上下文都断了**。

现在多了一个更优雅的选择。

## 用法极简

```raw
/handoff feishu
```

就这一行。

敲完回车，CLI 提示"正在等待 Gateway 接手"。几乎同时，飞书"叮"地弹出一条消息——Hermes 已经在那里主动跟你打招呼了：

> "嗨，刚从 CLI 搬过来的，我们之前在改 Python 爬虫，分析到 requests 超时重试那块，你继续说。"

然后 CLI 自动退出。你锁屏出门就行。不用截图，不用复述，连你跟它吐槽过的报错日志，它都记得一清二楚。

## 背后发生了什么

作为技术人，你肯定好奇这是怎么做到的。简单说，CLI、本地数据库和后台网关（Gateway）打了一套跨端配合，总共三步：

**① 终端打标** → 你敲下 `/handoff feishu`，Hermes 先做几项检查：飞书配好没？Home Channel 设了没？确认无误后，在本地数据库给当前会话打上标记——"等待跨端漫游"。

**② Gateway 接管** → 后台常驻的 Gateway 进程每 2 秒轮询一次，发现这条标记就自动接手。它把飞书聊天绑定到你的会话 ID 上。如果飞书支持 Thread，还会建个同名话题：`Hermes — 你的会话名`。

**③ 注入上下文，终端退场** → Gateway 构造一条虚拟 Prompt 给大模型："这个会话刚从 CLI 转过来，完整历史已加载，请总结我们在做什么。"大模型的回复推到飞书，CLI 功成身退。

回到电脑想继续？随时可以：

```raw
hermes --continue 你的会话标题
```

或者进 CLI 输入 `/resume 会话标题`。一个灵魂，多个躯体，说切就切。

## 两个真实场景

**场景一：写脚本写到一半要出门**

电脑上让 Hermes 帮我写 Python 脚本，写到一半手机响了。`/handoff feishu`，关电脑走人。地铁上打开飞书，Hermes 已经在等："我们刚才在写 XX 脚本，还差 API 对接部分。"我在路上把参数告诉它，到了公司 `/resume`，后半段已经写好了。

**场景二：debug 到深夜，明早手机上接着看**

凌晨在终端调一个诡异的 bug，排查了七八轮，定位到大概率是某个 race condition。太晚了不想继续。`/handoff telegram`。第二天早高峰路上打开 Telegram，Hermes 把排查思路和几个修复方向都列好了，我在地铁上确认方向，到公司直接开干。

**一个对话，三种入口**——CLI、飞书、Telegram，随时切换，上下文不丢。

## 准备工作

要体验这种丝滑切换，需要满足两个条件：

**1. Gateway 必须在运行**

后台需要有 `hermes gateway run` 跑着，你可以用 `hermes gateway status` 检查。没有 Gateway 在后台，转交会超时失败。

**2. 提前设好 Home Channel**

在飞书私聊里先跟 Hermes 说句话，然后输入 `/sethome`。这是告诉 Hermes："下次我让你把对话端过来，就端到这个频道。"

## /handoff vs /resume

经常被问到，handoff 和 resume 两个命令的区别：

- **`/handoff`** = **搬家**。方向是 CLI → 消息平台，CLI 自动退出，需要 Gateway 在后台运行。典型场景：设备切换。
- **`/resume`** = **回家**。恢复一个旧会话，任何平台都行，不需要 Gateway，CLI 不退出。典型场景：继续之前的对话。

## 总结

`/handoff` = 一条命令，把终端对话搬到手机上。

对于每天在电脑、会议室、地铁、滴滴之间切换的开发者来说，这个命令能帮你省下大量重新拉齐上下文的烦躁时间。下次再遇到"拔腿就走"的情况，记得敲一句。
