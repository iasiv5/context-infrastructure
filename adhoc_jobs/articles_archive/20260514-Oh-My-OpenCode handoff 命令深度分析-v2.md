# Oh-My-OpenCode /handoff 命令详解：AI 会话的存档与读档

## 一句话说明

`/handoff` 是 oh-my-opencode（现已更名为 oh-my-openagent）插件里的一个内置命令。作用很直白：让 AI 把当前会话里最关键的上下文，压缩成一份结构化的"交接文档"。你把它复制粘贴到新会话，就能接着干——像游戏里的存档读档。

> 源码位置：[oh-my-openagent/src/features/builtin-commands/templates/handoff.ts](https://github.com/code-yeongyu/oh-my-openagent/blob/dev/src/features/builtin-commands/templates/handoff.ts)

## 为什么需要它？

所有 AI 对话都有上下文窗口限制。聊得越多，早期信息越容易被"挤掉"，AI 的回答质量就开始走下坡路——重复自己说过的话、忘掉之前敲定的方案、甚至前后矛盾。

常见的应对方式要么是硬扛，等会话自己做自动压缩（compact）；要么手动把重要内容复制出来，自己整理。`/handoff` 做了一次半自动化的尝试：让 AI 替你总结、替你格式化，你只管复制粘贴到新会话。

## 生活里的比喻

暑假作业写到一半，妈妈喊你吃饭。你会顺手在纸上记几笔：

- "数学做到第3题，第4题要用勾股定理"
- "作文写到了去海边那段"
- "英语第5页没做"

吃完饭回来看一眼，就能接着写。

`/handoff` 干的就是这件事，只不过换成 AI 帮你写纸条。

## 运行机制：4 个阶段

### Phase 0：值不值得做？

先看一眼当前会话：有没有足够的上下文值得交接？如果你刚开了个新会话、几乎没聊什么，它会直接告诉你"没什么可交接的"，不浪费时间生成一份空文档。

### Phase 1：自动收集数据

AI 并行调用 4 个工具抓取信息：

```
session_read()  → 读取整个会话历史
todoread()      → 读取当前任务进度（todo 列表）
git diff        → 最近改了哪些代码
git status      → 哪些文件还没提交
```

这一步是全自动的，不需要你手动指定"保留哪些、丢掉哪些"。

### Phase 2：提取关键信息

拿到原始数据后，AI 从中提炼四类关键信息：

- **用户原话**——你提的需求原文，一字不改、不做意译（防止 AI 用自己的理解"翻译"掉你的真实意图）
- **已完成的工作**——做了什么、动了哪些文件
- **未完成的任务**——还差什么没收尾
- **关键决策**——为什么选了方案 A 而不是方案 B，当时的理由是什么

提取规则：用第一人称叙述（"我做了..."），聚焦行为和能力，不纠结具体变量名或代码行号。

### Phase 3：按固定格式输出

最终输出一份结构化文档：

| 区块 | 内容 |
|------|------|
| **USER REQUESTS (AS-IS)** | 你的原始需求，一字不改 |
| **GOAL** | 一句话说明下一步该干嘛 |
| **WORK COMPLETED** | 已完成的工作清单 |
| **CURRENT STATE** | 代码和环境的当前状态 |
| **PENDING TASKS** | 没做完的任务 |
| **KEY FILES** | 最重要的文件，最多 10 个 |
| **IMPORTANT DECISIONS** | 做过的技术决策及原因 |
| **EXPLICIT CONSTRAINTS** | 你明确要求遵守的约束 |
| **CONTEXT FOR CONTINUATION** | 下一轮会话需要知道的补充信息 |

拿到这份文档之后，操作很简单：

1. 开一个全新的会话
2. 把整份 handoff 文档粘贴进去
3. 在末尾加上你的新指令，比如："从上面的交接文档继续，接下来帮我做 XXX"

## 实际应用场景

**场景一：长项目开发，上下文快满了**

你跟 AI 搓了 3 小时前端，创建了 20 多个文件，上下文快顶到天花板。这时输入 `/handoff`，AI 生成交接文档。开个新会话粘贴进去，接着做用户注册功能，不用把项目结构从头讲一遍。

**场景二：Bug 调试到一半要换会话**

API 报 404，AI 查了 3 个文件，定位到问题出在 `src/routes/api.ts` 第 42 行的路由配置，但还没来得及改。`/handoff` 把排查结论和定位信息全部记下来，新会话里直接动手修。

**场景三：团队协作交接**

你要把手上的活儿交给同事。`/handoff` 一键生成包含关键决策、文件结构、未完成工作的交接文档。同事拿着它开个新 AI 会话，不用你口头再交代一遍。

## 和 /compact 有什么区别？

| | /compact | /handoff |
|--|---------|---------|
| **做什么** | 压缩当前会话的上下文（原地瘦身） | 生成一份独立的交接文档（打包带走） |
| **会话是否继续** | 继续在当前会话里聊 | 需要手动开新会话 |
| **适用场景** | 上下文快满了但还想继续聊 | 要换会话、换设备、或交给别人 |

## 要注意的点

- **不会自动开新会话**——它只负责生成一段文本，复制粘贴的动作得你自己来
- **依赖 LLM 生成内容**——但不会调用"创建新会话"之类的平台 API，纯粹是 prompt 驱动
- **垃圾进垃圾出**——如果原始会话里信息就很乱，交接文档的质量也不会高到哪去
- **是插件功能，不是内核功能**——由 oh-my-opencode / oh-my-openagent 实现，OpenCode 本体不自带

## 一句话总结

`/handoff` = AI 替你写的"会话存档"。换个新窗口，粘贴进去，接着干。
