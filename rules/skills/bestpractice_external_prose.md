# 外部中文 Prose 诊断与 Voice Contract 指南

## 元数据

- **类型**：Manager Reference
- **适用场景**：Main Agent 诊断外部中文文章的叙述距离、认知负荷与段落架构，并提炼一页以内的 `voice_contract.md`。
- **使用限制**：仅供 Main Agent 阅读，严禁原样传递给 prose Writer。
- **最后更新**：2026-07-23

## 1. 使用边界与编辑职责

本指南是 Main Agent（Manager）的诊断手册，绝不可整份塞进 prose Writer 的生成上下文。

自然中文不是满足数百条禁令后的剩余区域。把复杂的分类法、历史失败与通篇规则堆给 Writer，只会稀释本题的声音焦点，并诱导模型用审计与讲义语言组织正文。

Main Agent 的核心职责：
1. **诊断姿态与架构**：识别稿件为何端着、像讲义、认知超载或表演式口语化。
2. **提炼契约**：根据本题证据与真实负例，编写一页以内的 `voice_contract.md` 送交 Writer。
3. **冷读验收**：基于全文通读体验与认知舒适度判定，区分整体声线失败与局部外科手术式（surgical）修饰。

## 2. 叙述姿态与距离：直接陈述发现

合格的 external prose 应当建立平等的同行叙述距离：作者直接向聪明但缺乏特定共享上下文的读者陈述已核实的变化与发现。

诊断时需要区分两种偏离方向：
- **教材声**：宣布主题 -> 下定义 -> 解释机制 -> 抽象总结意义。像课程讲义，将读者视为受训对象。
- **表演式口语**：滥用俚语、夸张比喻、假对话或过多第二人称。用形式亲切掩盖机制未解释清楚。

正向叙述姿态的约束与特征：
- **叙述距离**：作者与读者面对同一个具体对象，沿动作、限制与后果推进；概念按需出现，判断落于证据之后。
- **载体真实性**：贯穿正文的具体场景与运行示例，必须严格基于 `source_contract.md` 或明确标注为假想示例。自然表达绝不能靠虚构现场事故、推测的用户反应或未受支持的因果细节来实现。
- **自然呼吸**：入口直接从本篇特有的新事实或冲突进入；长句说原因、短句落判断；段落停在观察后果或未决问题上，不强加宏大总结。

## 3. 信息架构与认知负荷诊断

声线失败常源于段落架构扭曲与认知负荷失控。

### 3.1 概念依赖与引入顺序
避免“先抽象定义，再讲使用”。顺畅的顺序是先展示真实痛点与动作（系统在什么情况下卡住 -> 采取了什么操作 -> 产生什么改变），概念在解决问题时顺理成章落地。

### 3.2 认知舒适度诊断 (Cognitive Comfort)
即使每个专有名词都已被单独解释，若段落强迫读者在脑中同时维护过多未落地的分类、比较轴或系统组件，仍属于认知负荷过载。诊断信号：读者必须暂停阅读、向前翻查或手动绘制关系才能理解后续推进。

### 3.3 有限集合比较与局部地图 (Local Map Rule)
当读者确实需要比较三个及以上的有限替代方案或并列项时，应在展开前先交代选项总数与统一的比较基准（局部地图）。不要把所有结构化比较或编号列表机械判为“教材声”；缺乏局部地图的连续展开反而会损害认知舒适度。

### 3.4 章节衔接与 H2 依赖
遮住相邻 H2 标题连读前节结尾与后节开头。自然的衔接由同一对象的下一动作、机制暴露的新边界或前一选择的后果驱动。若只能靠标题补出因果，说明两端交接需要重写。

### 3.5 模式词作为诊断信号
类似“这是一个...”、“要理解 X 必须先理解 Y”、“这表明/意味深远”等表达，是定义式入口、抽象主语或总结尾巴的**诊断信号**，而非单纯的禁词。发现信号应重构段落推进，而非做同义词替换。

### 3.6 过度压缩不是低认知负担

另一种常见失败是把文章压成“机构名 + 一句定性”“法域名 + 一句差异”“建议 + 一句 checklist”。事实可能都对，读者却没有经历旧安排、具体动作和新后果之间的因果链。低认知负担不是删去解释，而是让读者在任一时刻只需要理解一个正在变化的对象。若每段压成一句后几乎没有信息损失，稿件只是正确提纲，必须回到文章架构而不是补几句修辞。

### 3.7 括号补译不是术语解释

“可观测能力（observability）”“provenance（来源链）”这类双写，通常只证明作者知道英文词，并没有帮助读者理解它在当前动作中的作用。除正式全称、缩写展开、原文引语或确有检索价值的首次名称外，不使用“中文（English）”或“English（中文释义）”。选择一个正文称呼，让后续动作解释它。

括号密度还是翻译体的早期信号。若一段删掉括号内容后意义不变，应直接删除；若删后无法理解，说明正文句法没有承担解释职责，需要重写关系而不是保留词条。

### 3.8 分析框架必须先熔融

时间线、两条轴、三层市场、四个问题和六项 checklist 都可以帮助 Main Agent 思考，但不能自动同时成为 H2、图片、正文列表和结尾总结。框架只有在读者确实需要拿它做判断，或它把前文已经出现的冲突压缩成更容易记住的形式时才应显式出现。

诊断时做 scaffold deletion test：删掉“两轴/三层/四问”等标签，具体对象、动作和后果是否仍能推动全文？不能，说明文章没有叙述骨架；能，则只保留真正降低认知负担的一处显式框架。

## 4. 怎样制作本题 Voice Contract

Main Agent 为 Writer 提供的 `voice_contract.md` 必须控制在一页左右，仅包含本题所需的正向与负向证据。

- **正向摘录 (Positive Excerpts)**：挑选 1-2 段用户明确认可、且解释难度相近的真实段落，注明要学习的推进节奏，切忌引导 Writer 机械套用句式。
- **负向摘录 (Negative Excerpts)**：直接截取**当前 draft** 中最典型的 2-3 段病态段落，点明其入口、推进或收尾的具体问题。真实负例远比通用禁词表有效。

### Voice Contract 模板

```markdown
# Voice Target

[2-3 句话说明谁向谁解释什么，以及应有的叙述姿态与距离]

## Positive Excerpts

[摘录 1-2 段真实优质段落]
- **学习重点**：[说明要吸收的段落推进或叙述节奏特征]

## Current-Draft Hazards

[截取当前 draft 中 2-3 段典型失败段落]
- **问题诊断**：[指明是定义式入口、表演式比喻还是抽象总结尾巴]

## Boundaries & Constraints

- 第一人称与问句的使用边界。
- 技术密度与解释深度限制。
- 局部地图与有限集合比较规范。
- 术语选择规则：选择中文或英文正文称呼，禁止词典式括号补译。
- [不超过 8 条高影响力的本题约束]
```

## 5. Main Agent 冷读验收标准

Main Agent 必须脱离生成自述与 QA 报告，直接通读候选正文。

### 5.1 验收硬门槛 (Hard Gate)
- **事实与来源保真**：数字、日期、URL、专有名词、归因与限制边界必须与 `source_contract.md` 严格一致。严禁包含未受支持的假想事故、用户心理推测或绝对化推论。一票否决。

### 5.2 整体声线与阅读体验判定
- **阅读体验与认知舒适度优先**：声线验收以通读体验为核心。整体自然、解释清晰且认知负荷适中的文章，即使偶尔命中一两个模式词，亦可放行或做外科手术式（surgical）修饰。
- **拒绝表面合规**：文章无一禁词，但呈现“宣布主题-下定义-抽象总结”的讲义节奏，或让读者维护过多的游离概念，判定为整体失败（RETRY 或退回 Round 1）。

### 5.3 冷读九问
1. 开头是在分享具体发现，还是在宣布接下来要教什么？
2. 遮住 H2 后，章节之间是否仍有自然发生的因果关联？
3. 概念第一次出现时，读者能否立刻理解其角色与后果？
4. 段落是否强迫读者同时维护过多未挂钩的新分类或比较轴？
5. 比较三个以上选项时，是否先给出了选项数量与比较基准？
6. 亲切感是源于清楚解释了现场机制，还是依赖俚语、表演式比喻或虚构细节？
7. 连续三段是否在“定义、分类、逐项解释、抽象总结”，却没有同一个具体对象继续发生变化？
8. 是否出现删掉仍不损失信息的中英括号补译？
9. 分析时使用的 taxonomy 是否被直接搬成了 H2、列表和结尾，而没有熔融进叙述？
