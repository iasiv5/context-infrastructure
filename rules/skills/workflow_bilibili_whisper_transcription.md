# 视频下载与语音识别工作流（Qwen ASR 优先）

## 元数据
- 类型: Workflow
- 适用场景: Bilibili/YouTube 视频批量下载 + 本地语音识别（默认 Qwen ASR 1.7B）
- 创建日期: 2025-02-12
- 最后更新: 2026-04-04
- 原项目已归档（不再保留在 workspace 中）

## 路径约定

- 临时下载与中间产物：`tmp/<task_name>/`
- 最终可长期保留的 transcript：`adhoc_jobs/videos_transcribe/transcripts/`
- 最终默认只保留**不带时间轴的纯文本脚本**，文件名建议：`YYYYMMDD_platform_videoid_short_slug.md`
- 音频、`.srt`、`.vtt`、`.tsv`、`.json` 等中间产物在 transcript 落盘后清理到废纸篓

## 核心流程

**三阶段工作流：**

1. **获取列表** → 使用 yt-dlp 提取视频ID（注意B站API限制，可能返回352错误）
2. **单线程下载** → 逐个下载音频，每次间隔2-3秒，避免触发反爬
3. **本地转录** → 默认运行 MLX Qwen ASR 1.7B；只有在兼容性或回归原因下才回退到 Whisper

## 关键决策

| 决策点 | 选择 | 原因 |
|--------|------|------|
| 下载并发 | 单线程 | 避免触发B站反爬机制 |
| 转录并发 | 多进程（4-8） | CPU密集，充分利用多核 |
| 模型选择 | 默认 Qwen ASR 1.7B | 时间轴默认不是主产物，全文更重要 |
| 输出格式 | 最终保留纯文本 transcript | 后续检索更稳定，中间产物可回收 |

## 默认选择：Qwen ASR 1.7B

当前推荐默认模型：`Qwen/Qwen3-ASR-1.7B`

理由：

1. 在 Apple Silicon 上可通过 `mlx-qwen3-asr` 本地运行
2. 对中文场景更友好
3. 在真实样本里比 Whisper 更少出现长串重复 hallucination
4. 多数视频转录场景并不需要逐字 timestamp，直接保留全文更符合后续检索和总结

推荐调用方式：

```bash
python adhoc_jobs/videos_transcribe/transcribe.py \
  --input input.mp4 \
  --output transcripts/output.md \
  --model Qwen/Qwen3-ASR-1.7B \
  --language auto
```

默认只保留全文；只有明确需要分段文本时再加：

```bash
--include-segments
```

## Whisper 作为 fallback

| 模型 | 参数量 | 速度（CPU） | 准确度 | 推荐场景 |
|------|--------|-------------|--------|----------|
| tiny | 39M | 1-2分钟/10分钟 | 较低 | 快速预览 |
| base | 74M | 2-5分钟/10分钟 | 中等 | 平衡选择 |
| small | 244M | 5-10分钟/10分钟 | 较高 | 日常使用 |
| medium | 769M | 10-20分钟/10分钟 | 高 | 高质量需求 |
| large-v3 | 1550M | 20-60分钟/10分钟 | 最高 | 最高质量要求 |

Whisper 仍可作为 fallback，尤其是：

- 需要复用旧工作流
- 需要和历史结果保持一致
- 明确要保留 Whisper 风格的时间轴输出

## Qwen ASR 使用经验

1. **默认不需要 timestamps**：绝大多数知识整理、视频摘要、全文检索场景，只关心最终 text，不关心时间轴。
2. **先保留全文，再决定是否保留分段**：全文是主产物，分段文本是可选 sidecar。
3. **1.7B 是当前默认，不是因为它绝对最准，而是因为它是更稳的默认起点**。
4. **如果目标是极低延迟或批量吞吐，可以考虑 0.6B**；如果目标是一次性高质量全文，先试 1.7B。
5. **在长静音/低信息段要警惕 Whisper 的重复 hallucination**；Qwen ASR 在这类样本上更保守，常常直接不输出或少输出。

## LLM 后处理

ASR 原始输出通常需要后处理：

1. **转换为简体中文** — 识别可能为繁体
2. **添加标点符号** — 根据语义添加逗号、句号、问号
3. **合理分段** — 按主题划分段落，添加小标题
4. **纠正术语** — 专业名词识别错误（如"木质布"→"木质部"、"筛管细胞"）
5. **优化可读性** — 调整语序、补充缺失内容

## 踩坑记录

| 问题 | 现象 | 解决方案 |
|------|------|----------|
| **352错误** | 请求被B站拦截 | 添加User-Agent/Referer headers，增加延迟，或手动获取ID |
| **404错误** | 视频已删除或ID错误 | 验证ID有效性，跳过无效视频，记录失败ID |
| **内存不足** | 多进程转录时内存溢出 | 减少并行进程数（4-6个），使用较小模型，分批处理 |
| **下载不完整** | .m4a文件无法播放 | 检查文件大小，重新下载，添加完整性验证 |
| **转录太慢** | large-v3单个视频20-60分钟 | 选择合适模型大小，使用GPU加速，分块处理长视频 |

## 最佳实践

**下载阶段：** 单线程 + 2-3秒延迟 + User-Agent headers + 只下载音频 + 记录失败ID

**转录阶段：** 默认 Qwen ASR 1.7B + `language=auto` + 默认只保留全文；需要分段时再开启 `--include-segments`

**落盘阶段：** 在 `tmp/` 完成下载和转录，整理出纯文本脚本后移入 `adhoc_jobs/videos_transcribe/transcripts/`

**清理阶段：** transcript 落盘后删除或回收音频、时间轴字幕和 sidecar 文件，只保留最终脚本

**质量优化：** 默认先试 Qwen ASR 1.7B；如果要和历史 Whisper 结果对齐，再切 Whisper fallback；必要时人工校对

**错误处理：** 实现重试机制，验证文件完整性，处理异常避免脚本中断
