# 外部写作与成文工作流

## 元数据

- **类型**: Workflow
- **适用场景**: 将已验证的调研素材转化为 external-facing 分析文章、公开 survey report 或外部课程/客户内容。
- **前置依赖**: [深度调研工作流](./workflow_deep_research_survey.md) Phase 1-3 的产出，或等价的已验证素材。
- **最后更新**: 2026-07-16

## 1. 目标与产出路由

本 skill 解决“素材充分，但文章像 AI 汇总”的问题。目标是形成一篇有且只有一个核心 thesis、陌生读者能复述、证据可核查的文章。

面向用户本人、内部协作者或未来 AI agent 的文档使用 [内部写作工作流](./workflow_internal_writing.md)。external-facing 调研分析默认产出 survey report，存入 `contexts/survey_sessions/`；只有用户明确要求博客时，才按目标项目的博客目录和格式处理。

## 2. 验收标准

1. **概念先于引用（一票否决）**：每个专有名词、法规、事件和技术术语在第一次引用前已有足够上下文。引入不等于字典定义，一句背景锚点通常已经足够。该约束贯穿全文，不只适用于开头。
2. **像自然介绍，不像教材（一票否决）**：文章应像一个真正理解问题的人在分享发现，不能连续采用“定义对象 → 解释机制 → 抽象总结”的课程讲义节奏，也不能用夸张比喻和俚语表演亲切。
3. **看得懂，也读得舒服（一票否决）**：概念依次到达，先沿具体对象或过程展示发生了什么，再给差异命名。不得把作者用于分析的多条分类轴直接变成读者的阅读顺序。
4. **单一 thesis**：核心判断具体、可被同意或反对，不是“复杂且值得关注”。
5. **Thesis 前置**：前 25% 交代问题、作者判断和读者增量。
6. **围绕读者组织**：按读者的疑问链推进，不按作者的分析维度罗列。
7. **作者连续性**：与相关 Axioms 和历史文章一致；若判断改变，正文交代新证据和变化原因。
8. **配图降低认知负担**：图片压缩机制、趋势或对比，包含 alt text 和正确相对引用，不作装饰。
9. **脚手架不可见**：最终稿不得出现 L1-L8、axiom 编号、Phase、Thesis Catalog 等内部术语。
10. **五秒继续阅读门控**：标题和开头让读者立即确认对象、核心判断和公开摘要之外的增量。

## 3. Thesis Mining Gate

用户尚未提供明确 thesis，或现有 thesis 尚未通过证据与反方压力测试时，先执行 [External-Facing Thesis Mining](./workflow_external_thesis_mining.md)。它读取 Axioms、Thesis Catalog、历史文章、目标发布环境中的相邻文章或历史语料，以及 research packet，输出 `tmp/<session_slug>/thesis_decision.md`。

只有 verdict 为 `PROCEED` 才能创建 `writing_brief.md`。`DO_NOT_WRITE_YET` 表示当前 topic 不能支撑有判断力的文章，应补证据或停止，不得为了完成任务强行生成 thesis。

用户已给出 thesis 时保留其判断，不重新发明方向；仍需检查证据、边界、最强反方、作者连续性和读者增量。低风险短文可以由主线程完成轻量检查，并把结果写入 brief。

## 4. Brief 与文风校准

撰写、重写和自查都必须加载 [外部文章微观文风与修辞规范](./bestpractice_external_prose.md)。`writing_brief.md` 至少包含：

- thesis、reader contract、3-5 个论证节点和最强反方；
- reader start state、target belief change 和 3-7 个有方向的因果 claim；
- 已核查事实、数字、URL、图片占位和结论强度边界；
- 每份核心证据在论证中的角色；
- 概念引入计划：列出陌生读者可能不认识的概念及首次引入位置；
- 产品名、模型名、API 名、代码标识符和易误译术语的不可改词表；
- 3-5 个来自不同判断角度的候选标题，以及最后选择的理由；
- 对最近 5-10 篇同渠道文章的标题与开头去重检查。

普通概念使用中文，不附无信息增量的英文括注。产品名、API、协议、代码标识符和通用缩写保留官方英文。

### 4.1 Reasoning Architecture Gate

Thesis 不是一句孤立观点，提纲也不是素材分类目录。动笔前先定义文章要让读者完成哪一次认知变化，再按理解依赖安排内容：

1. **Reader start state**：目标读者起初怎样理解这个对象，缺少哪些必要前提。
2. **Target belief change**：读完后，核心理解从什么变成什么。它必须比“了解该产品或事件”更具体，并且能被同意或反对。
3. **Causal model**：用 3-7 个有方向的 claim 写出 thesis 的因果依赖。
4. **Evidence roles**：每份核心证据负责建立旧模型、证明变化、解释机制、验证判断还是限制外推。没有明确角色的材料不进入正文。

Brief 还必须包含一份 **Voice Route**。它不替代提纲，而是防止 claim graph 被写成教材：

1. **Opening oddity / observation**：本篇最值得主动讲给朋友听的反差、异常或变化。
2. **Author stake**：可选的一句轻量第一人称，只用于说明作者为什么在意，不承担情绪表演。
3. **Reader question chain**：每一节回答读者此刻自然会追问什么，不写成“本节介绍 X”。
4. **Concrete consequence anchors**：每节至少有一个可观察动作或后果。
5. **Tone hazards**：分别列出本题容易出现的教材句式和表演式口语。
6. **Concrete carrier / running example**：比较三个以上抽象对象时，优先用同一个任务、人物、请求或业务记录贯穿多节。

分析框架可以帮助作者发现 thesis，但默认不能原样进入正文。除非文章本身要教读者操作该框架，否则应沿具体过程展示差异，等读者已经看见差异后再命名。每一节都必须回答四个问题：它改变读者的哪项理解；所需前提是否已经出现；由哪个具体对象、动作或后果承载；读者是否需要同时记住多个尚未落地的新概念。

### 4.2 标题：最短的阅读合同

标题同时完成三件事：确认文章对象、说明与读者的相关性、显示正文相对公开信息的增量。

- 陌生公司、论文或协议同时带出类别、动作或变化。
- 事件驱动文章写出新闻对象或具体变化。
- 分析增量应落在机制、演进、竞争位置、边界或决策影响，不只复述“发布了什么”。
- 准确优先，不用标题党、虚假悬念和夸大因果；可以直接交付判断。
- 不默认使用“不是 A，而是 B”“为什么 X 正在成为 Y”“趋势还是噱头”等模板。

替换测试：换掉公司名、论文名或事件名后，标题若仍能原样用于十篇文章，就没有表达本篇身份。IC-3 后再次核对标题与正文；文章增量在写作中变清楚时，应同步调整标题。

### 4.3 开头：让证据决定入口

开头不设统一模板。具体场景、第二人称代入、事故或定义都不能成为默认算法。标题提出阅读承诺，开头立即确认对象、判断和增量，不用气氛、感怀、泛泛历史或概念定义拖延主题。

入口应服从本篇最有辨识度的证据：日志可从真实时间线进入；论文可从关键结果或测量方法进入；产品发布可从关键设计选择进入；技术演进可从转向、弃用或约束变化进入；市场分析可从分类结论或最强替代路径进入；没有独特入口证据时直接给判断，不制造场景。

具体信息必须来自证据，不得虚构步骤数、人物动作、事故过程或用户反应。事件驱动文章在首屏完成“事件锚定 + 分析增量”。最晚读完前 2-3 段，读者应能复述发生了什么、文章认为它改变了什么、为什么需要继续读。

开头也做替换测试。若替换对象名后仍能用于十篇文章，它更可能是模板。读取最近 5-10 篇同渠道文章的前 150-300 字；最近五篇已有两篇使用同类入口时，新文章不得无理由复用。

开头还要检查作者既有观点的连续性。不要只搜索当前产品名或事件名；按问题和概念检索历史文章，判断当前对象是在填补、修正还是反驳旧判断。若这种连续性比孤立介绍新品更能解释“为什么是现在”，默认用一两句话承接旧判断，再引入当前对象。Brief 记录旧判断摘要、当前关系、旧文 URL，以及采用或放弃该入口的理由。

## 5. AGY 两遍成文与独立 Prose QA

所有写作 Agent 都按 [Antigravity CLI 文件式调用](./antigravity_cli.md) 执行。

| 角色 | 执行模型 | 输出工件 | 职责 |
|---|---|---|---|
| 主线程 Manager | 主模型 | `tmp/<session_slug>/writing_brief.md` | 调研、事实核查、thesis gate、reasoning architecture、Voice Route、概念规划、最终配图和验收 |
| IC-1 结构稿 | AGY / `Gemini 3.5 Flash (High)` | `tmp/<session_slug>/article_structural.md` | 按 claim dependency graph 写齐论点、证据、概念、链接和图片；标明 reader question 与 concrete consequence，不追求发布级 prose |
| IC-2 自然介绍重写 | fresh AGY / `Gemini 3.5 Flash (High)` | `tmp/<session_slug>/article.md` | 读 brief、结构稿和同渠道校准样本，只继承 claim graph 与硬约束，从 Voice Route 重新讲述全文 |
| IC-3 独立 Voice QA | fresh AGY / `Gemini 3.5 Flash (High)` | `tmp/<session_slug>/article_qa.md`、`prose_qa.md` | 先判断整篇声线和认知舒适度，再审改 prose；不改变 claim、事实、证据、数字、URL、图片或结构意图 |
| Manager Voice Pass | 主模型 | `tmp/<session_slug>/article_final.md`、`voice_audit.md` | 清除翻译腔和叙述距离问题，完成不变量与 new-claim audit；不改变 brief 授权的事实、结构或结论强度 |

IC-1、IC-2、IC-3 分别使用新的 `agy --print` conversation，不带 `--continue` 或 `--conversation`。每阶段独立保存 `agy_icN_prompt.md`、结果文件、`agy_icN_stdout.txt`、`agy_icN_stderr.txt` 和 `agy_icN_events.log`。默认内部 timeout 10 分钟，外层约 610 秒，并同时启用 sandbox 与非交互权限确认。

所有 brief、校准材料、prompt、草稿、审查报告和运行日志都放在 gitignored 的 `tmp/<session_slug>/` 下，避免未发布内容和本地路径进入版本控制。

每阶段完成后，主线程检查退出码、结果文件非空、stderr 无未处理错误，以及数字、URL、图片、结构和不可改词表。stdout 自述不能替代结果验收。

### 5.1 IC-2：从结构稿重新讲述，而非润色

低认知负担有三个门控：读者遇到概念时是否已有上下文；文字是否像一个真实的人顺着问题解释；读者是否需要同时记住多个尚未落地的新概念。只做到“概念都有定义、句子都很短”仍可能写成教材。

IC-2 读取结构稿是为了取得 claim、证据位置、URL、数字和章节依赖，不是为了润色原句。每节先还原成“读者问题 → 具体动作或后果 → 判断”，再从空白页面重写。若成稿连续保留结构稿两段以上相同的段首逻辑，默认重写失败。

比较多个方案时，优先让同一个请求、工单、人物或数据记录贯穿各节。动作先于分类，术语延迟命名，一段只推进一个主关系。H2 应能脱离正文冷读；若标题只有掌握文章内部 taxonomy 后才成立，改成动作、变化或读者问题。

每次 IC-2 动笔前，从同一发布渠道选择 3-5 篇近期、经过人工打磨且解释难度相近的成稿。`tmp/<session_slug>/style_calibration.md` 记录正向样本路径、值得学习的段落和口吻特征，以及本次结构稿中的教材端与表演式口语负例。校准目标是叙述距离，不是复制句式、开头或比喻。

验收时出声念开头三段和每个 H2 的第一段。逐节检查：零背景读者能否理解首次出现的概念；能否不用新术语复述谁做了什么；是否频繁停顿或回读；删掉比喻和俚语后机制是否仍清楚。

### 5.2 IC-3：独立权限边界

IC-3 在同一个 fresh session 内先审后改。先只读开头、每个 H2 的第一段和结尾，判断整篇是在自然介绍发现，还是按提纲授课。三处以上出现“宣布主题 → 定义对象 → 抽象总结”的教材节奏时，必须整篇重写 prose，不能只替换词。

随后分别检查：概念首次出现、标题与开头、自然中文、认知舒适度、AI 模板与脚手架泄漏、局部连贯、重复、同渠道口吻、过度口语化，以及正文是否残留只有看过编辑对话才成立的问题。

IC-3 可以拆句、合句、换词、改局部段落、调整段落断点和小标题；整篇声线判定失败时，也可以在保持 claim、事实、数字、URL、图片和主要章节顺序的前提下重写全部 prose。不得增删 brief 授权的 claim，也不得改变事实归因、thesis 或结论强度。

需要新增事实、改变 thesis、重排主要章节、删除读者不需要操作的分析框架或重做证据链时，IC-3 不自行修复，在 `prose_qa.md` 标记 `BLOCKER`。主线程回到事实核查、brief 或 IC-1。

`prose_qa.md` 必须分别记录 comprehension gate 与 cognitive comfort gate，并包含整篇声线判定、主要修改、至少 4 组真实 before/after、标题冷读与复述测试、保留不动的数字/URL/图片数量、过度口语化扫描和 blocker 状态。两项 gate 都通过且没有 blocker，`article_qa.md` 才能进入 Manager Voice Pass。

### 5.3 Manager Voice Pass

最终 prose 质量不能外包给 IC-3 自我认证。主线程逐段清除四类问题：凭空创造的角色名称；把普通动作写成机构语言；从系统视角描述结果；用抽象名词代替读者实际失去的东西。`voice_audit.md` 记录所有实际改动的原句、问题和改写，不能只写“已消除翻译腔”。

Voice Pass 后机械比较 `article_qa.md` 与 `article_final.md`：数字一致，URL 数量和目标一致，图片引用一致，H2 顺序一致，diff 没有新增、删除或加强 brief 授权的 claim。还要对照 brief 和 research packet 做 new-claim audit；IC-3 为了亲切而新增、但没有证据支持的专名、因果关系、性能判断和绝对化词必须删除或降回已验证口径。这类未经授权的新增内容不受 claim 不变量保护。

## 6. 配图

配图是 external-facing 文章的硬约束。图片必须承担机制压缩、趋势或对比表达，使用目标项目支持的 PNG/JPG/WebP 等发布格式，控制体积，并在 Markdown 中使用 alt text 和相对路径。定量图先保证数据准确，再做视觉优化。不要让装饰性图片替代证据。

## 7. Post-writing Scans

IC-3 完成语义审查并经过 Manager Voice Pass 后，主线程对 `article_final.md` 运行确定性回归扫描。Manager 在 Voice Pass 权限内修正机械文风命中；若问题需要 IC-3 重写，则重新生成 `article_qa.md`，随后必须重跑 Manager Voice Pass 和全部扫描：

```bash
# 破折号
rg -n '——' <file>

# “很 + 评价词”
rg '很[直接清楚简单明显重要透彻全面深入关键]' <file>

# 内部脚手架
rg 'L[0-8]|axiom|Phase [A-Z]|叙事重构|技术族谱|瓶颈迁移|Thesis Catalog' <file>

# 元评论、评价标签和禁用表达
rg -n '说得.{0,5}更|直白到|不需要转述|本身就说明|本身就有点|很容易漏掉|用不着在推理|值得|长出来|长出了|生长' <file>

# 被动语态，逐项判断
rg -n '被' <file>

# 图片引用
rg -n '!\[[^\]]+\]\([^\)]+\)' <file>

# 中英混排硬伤
rg -n '\b(of|and|the|to|in|for|with|or|but|is|are|was|were)\b' <file> | rg -v 'https?://|!\[|^\s*#\|^\s*>'

# 无信息增量双语括注
rg -n '[\p{Han}”’」』][（(][A-Za-z][A-Za-z0-9 _./+:-]{1,50}[）)]' <file> | rg -v 'https?://|!\['

# 长条件从句与抽象结论尾巴
rg -n '(^|[。！？]\s*)当.{8,60}(时|时候)[，,].{0,40}(就|会|成为|变成|意味着)|成为(一个|了).{0,8}(明显的)?问题|带来(了)?新的挑战' <file>

# 机械“可 X”排比
rg -n '可[\p{Han}]{1,6}[、，,]\s*可[\p{Han}]{1,6}([、，,]\s*可[\p{Han}]{1,6})?' <file>
```

概念引入、教材声、认知舒适度和过度口语化都不能由正则完成。IC-3 必须在 `prose_qa.md` 明确记录。主线程分别比较 `article.md` → `article_qa.md` 和 `article_qa.md` → `article_final.md` 的数字、URL、图片数量和目标地址，并检查 H2 顺序、证据段和结论强度没有越权改变。最后再检查新增标题、否定句和解释句：读者是否从正文已经知道为什么此刻要解释；删章后是否仍有未兑现的开头承诺、结尾问题、链接或配图。

## 8. Final Read Gate

全部写作、配图、事实核对和扫描完成后，主线程必须用当前 harness 的文件读取工具，从文件开头读取一次最终交付的 Markdown 文件。读取必须发生在最后一次修改之后，不能用 brief、临时稿、局部 grep 或 diff 代替。

读取后原则上不再修改。若发现必须修正的机械硬伤，修正后再次读取最终文件。最终回复提供该文件的 Markdown 链接。

## 9. 交付终点

最终 Markdown 和配图保留在本地工作区即为交付终点。不得自动发布到 blog、Twitter、Circle 或其他渠道。任何外发动作都需要用户对当次发布作出显式指令。
