# 外部写作与成文工作流

## 元数据

- **类型**: Workflow
- **适用场景**: 将调研素材转化为有判断力的 external-facing 分析文章、公开 survey report 或面向外部读者的课程/客户内容。
- **前置依赖**: 深度调研工作流（`workflow_deep_research_survey.md`）的 Phase 1-3 产出（或等价的已验证素材）。
- **创建日期**: 2026-04-28
- **最后更新**: 2026-07-11

---

## 1. 这个 skill 解决什么问题

调研素材充分但写出来像 AI 汇总，缺乏作者的分析视角和判断框架。本 skill 规范了如何把“事实”变成“一二句话能说清核心 Thesis 的可复述分析文章”。

*   **适用边界**：面向没有共享上下文的陌生读者、公开发布渠道、客户或外部课程受众。面向用户本人、内部协作者或未来 AI agent 的内部文档用 `workflow_internal_writing.md`。
*   **产出类型判断（动笔前必须先做）**：external-facing 调研分析的**默认产出是 survey report**，存 `contexts/survey_sessions/`。只有当用户明确说“写博客”、“发到博客”时，才按博客处理，存 `contexts/blog/content/`。

## 2. 验收标准：好的 external 文章长什么样

写完后对照以下标准进行结果验证：

1.  **非专家能看懂并复述 thesis（一票否决门控）**：任何不在该领域工作的聪明人，听完出声念后，能用一两句话复述文章在说什么。在任何一节出现理解摩擦，即说明背景假设或信息密度出了问题。
2.  **有明确的核心 thesis**：文章有且仅有一个核心判断，是具体的、可被同意或反对的观点，而非“复杂且值得关注”等笼统描述。
3.  **Thesis 前置**：前 25% 读完，读者必须清楚：讨论什么问题、作者的判断是什么、读完能得到什么。
4.  **围绕读者组织**：按照读者的疑问链/需求链推进，不按作者的分析维度罗列。
5.  **与既有观点体系一致**：与作者已有的核心观点、axiom（`rules/axioms/`）或同主题既有文章 consistent。如有修正，须在正文自然交代新证据及改变原判断的原因。
6.  **配图降低认知负担（硬约束）**：配图能压缩机制、展示趋势或对比，绝非装饰，且必须完成正文相对引用与 alt text 描述。
7.  **分析框架不可见**：所有 Thesis Catalog（L1-L8）、axiom 编号、Phase 阶段等写作“脚手架术语”在最终稿中零出现。
8.  **五秒继续阅读门控**：读者扫过标题和开头前几句后，能立即确认三件事：文章讲的是自己点进来的对象或事件；作者的核心判断是什么；继续读还能获得公开摘要没有提供的机制、边界、反例或后果。

## 3. 从素材到 Thesis 的发现（Thesis 发现）

如果用户尚未提供明确的 thesis，使用以下工具在 `tmp/<session_slug>/scratchpad.md` 中发现并合成 thesis：

1.  **视角匹配**：阅读 [Thesis Catalog 启发性分析视角](./reference_writing_thesis_catalog.md)，挑选 1-3 个与话题强相关的视角作为灵感，拒绝强套框架。
2.  **搜索作者已有写作**：检索 `contexts/blog/`、`contexts/survey_sessions/`、`rules/axioms/` 以获取历史观点和相似公理。
3.  **读取目标环境的既有文章**：阅读目标发布环境中 3-6 篇相邻或同主题文章，判断新文如何做增量、补空白或修正，避免复现外部媒体俗套叙事。
4.  **多模型 thesis brainstorm**：定稿前利用并行 sub-agent 发散（执行遵循 `workflow_parallel_subagents.md`，使用 `multi_tool_use.parallel` 在单条消息内发出）。建议配置：
    *   `gemini_3.5_flash`：负责读者入口和低认知负担。
    *   `glm`：负责反向发散和盲点探测。
    *   `reasoning_gpt`：负责论证强度、证据风险和一致性审计。
5.  **主线程整合**：主线程对 sub-agent 的发散结果做深度整合。整合必须产出并落盘：
    *   **Thesis statement**（2-3 句话，观点明确、非专家可懂）。
    *   **论证骨架**（3-5 个要点，匹配视角与最强证据）。
    *   **证据风险与归因限制**。

## 4. 写作执行原则与文风校准

在撰写、重写及自查阶段，必须加载并严格遵循 [外部文章微观文风与修辞规范](./bestpractice_external_prose.md)。
*   必须拆开长定语，将抽象主语换成人和动作。
*   严禁在段首和标题中使用范畴名与无信息增量的编号。
*   严禁使用“不是 X 而是 Y”的强硬 AI 模板，改为直接陈述或轻对照。
*   严禁无信息增量的“中文（English translation）”双语括注。产品名、API、协议、代码标识符和通用缩写可保留英文；普通概念使用中文即可。

### 4.1 标题设计：最短的阅读合同

标题用最短篇幅完成三件事：确认文章对象、说明它与读者的相关性、显露文章相对公开信息的分析增量。标题提出承诺，开头确认承诺，正文完成承诺。

陌生公司、论文或协议必须同时带出类别、动作或变化。事件驱动文章原则上写出新闻对象；分析文章提示正文将提供机制、演进、竞争格局、边界或决策影响。准确优先，不用标题党、虚假悬念和夸大因果，也不靠藏答案维持点击。

标题不设固定模板。不要默认使用“不是 A，而是 B”“为什么 X 正在成为 Y”“X 到底是趋势还是噱头”“别再 X 了”。做替换测试：如果换掉公司名、论文名或事件名，标题仍能原样用于十篇文章，它就没有表达本篇身份。

生成 `writing_brief.md` 时，先写 3-5 个来自不同判断角度的候选标题，不要围绕同一模板做同义改写。选择前对照最近 5-10 篇同渠道文章，避免连续复用问句、对照句、祈使句或“从 A 到 B”。IC-2 成稿后再复核标题与正文是否仍匹配。

### 4.2 开头设计：让证据决定入口

不把具体场景、第二人称代入、异常事故或“先讲现象”当成默认算法。动笔前先问：这篇文章最有辨识度、最能承载 thesis 的证据是什么？真实日志可从第一条异常进入，论文可从关键结果进入，产品考古可从转向或弃用进入，市场分析可从分类结论或最强替代进入；没有独特入口证据时，直接给判断，不制造情景。

具体信息必须来自证据。不要为了画面感虚构步骤数、人物动作、事故过程或用户反应。事件驱动文章的标题或首屏必须明确提到该事件，并立即给出分析增量。避免从遥远历史开始、迟迟不提当前事件的“考古式绕行”，也避免只复述公开报道、后文没有新判断的“新闻摘要封顶”。最晚读完前 2-3 段，读者应能复述：发生了什么，文章认为它真正改变了什么，为什么还需要继续读。

开头同样要做替换测试，并在生成 `writing_brief.md` 前对照最近 5-10 篇同渠道文章的前 150-300 字。若最近五篇已有两篇使用同类入口，新文章不得无理由继续沿用。

## 5. 两遍成文与模型分工协议

交付外部文章是主线程与写作子 Agent 精密协作的结果。

| 角色 | 执行模型 | 输出工件 | 职责 |
| :--- | :--- | :--- | :--- |
| **主线程 (Manager)** | 主模型 | `tmp/<session_slug>/writing_brief.md` | 负责 Phase 1-3 调研、事实核查、Thesis 生成、撰写 brief 骨架（含负例对）、最终配图生成 |
| **结构稿 Agent (IC-1)** | `gemini_3.5_flash` | `tmp/<session_slug>/article_structural.md` | 读 `writing_brief.md`，先写一版结构完整稿：论点、证据、段落顺序、链接和图片占位必须齐备 |
| **低认知负担重写 Agent (IC-2)** | `gemini_3.5_flash` | `tmp/<session_slug>/article.md` | 读 `writing_brief.md` + `article_structural.md`，保留 thesis、证据、链接、图片引用和结构意图，整篇重写为低认知负担版本 |

### IC-2 低认知负担重写的具体手法

IC-2 的本职是把"论文腔/端着"降成"在跟一个聪明但外行的读者讲话"。光说"低认知负担"不够具体，gemini 容易写成翻译腔摘要。重写时必须做以下四件事，每一条对照 `bestpractice_external_prose.md` 第 5 节的负例对：

1. **不要默认从定义开始，让本篇证据决定入口**。定义通常不是陌生读者的最佳入口，但替代方案也不应固定成第二人称场景。按照第 4.2 节选择本篇特有的关键事实、异常结果、产品决策、历史转折、真实经历或直接判断。先让读者接触最有信息量的材料，再在必要时给它命名。
2. **抽象主语拆成人和动作**。把"该现象的发现催生了新判断"改成"maille 翻了 39 万条记录，发现……"。把"失效发生在推理层"改成"出问题的是模型'想'的那一层"。凡是一句话主语是"现象""机制""失效面""范式"这类范畴词的，先问能不能换成具体的人做了什么动作。
3. **短句推进，每句一个动作**。一句不超过 30 字。长定语拆成独立短句，用句号或冒号断开，不用"的"叠两层。"把思考做成了独立且可调度的层"拆成"模型多了一层'思考'。这一层能单独计费、单独调度。"
4. **日常词替代术语化表达**。"基准评测无法覆盖"→"评测看不出来"。"新失效面"→"一种新的坏法"。"单调恶化"→"一个月比一个月糟"。技术名词（reasoning、doom loop、benchmark、token、adaptive thinking）保留英文，但描述它们的动词和形容词用日常中文，不用"催生""赋能""承载""映射"这类端着词。

验收硬门槛：写完后出声念一遍开头三段。任何一句念着像念论文摘要、需要回头重读才能懂的，重写那一句。

### 0. 主线程 prose 把关权限由其底座模型决定

IC-2 产出的终稿就是交付稿。主线程是否对它做 prose 质量把关，取决于主线程跑在什么模型上：

- **主线程是 Gemini 系列（含 `gemini_3.5_flash`）**：可以按本节后面的"越界改写阻断"流程做 prose 质量把关，因为同族模型改同族 prose 不会引入异种文风。
- **主线程不是 Gemini 系列（Opus / DeepSeek / GPT / GLM 等）**：**禁止手工修改 IC-2 的 prose**。终稿直接采用，主线程只允许做三类纯机械核查：(a) 数字是否与 brief 的"数字精确性硬约束"一致，(b) inline link URL 是否齐全且可达，(c) Markdown 语法是否正确（图片占位没有被反引号包裹成代码块、H1 不重复等）。发现文风问题不修，记进 brief 的"写作复盘"留给下一次 brief 写得更准。非 Gemini 主线程去改 Gemini 的中文 prose，只会把异种模型的文风偏好塞进去，越改越糟。

### 1. 为什么采用"两遍成文"
第一遍（结构稿）解决"说什么"，把 thesis、证据位置、反对意见、图片引用、inline links 和段落顺序放对。第二遍（低认知负担重写）解决"怎么让人不费劲地读进去"。
*   短文（<1000 字）、内部 memo、或用户明确要求快速草稿时，可以跳过第二遍；面向外部读者的分析文章默认不能跳过。

### 2. 越界改写阻断：三问 gate（仅对 Gemini 系列主线程生效）
本节只对"主线程是 Gemini 系列"的情况生效。非 Gemini 主线程直接采用 IC-2 终稿，不进这个 gate。

主线程在交付前，一旦产生"推翻/大面积手工修改第二遍 prose"的冲动，必须强制回答以下三个问题。任何一个答不上来，必须回到重写 brief 重新跑第二遍：
1.  推翻理由是否属于以下硬理由之一：(a) 事实缺失，(b) URL 丢失，(c) 结构不符合 brief，(d) 成品质量硬伤，(e) 低认知负担门控失败。若只是"语感不对"等主观 taste，禁止手工大修。
2.  觉得不对味的感受，其依据来自 `COMMUNICATION.md` 或 `bestpractice_external_prose.md` 的明文规则，还是来自主观偏好？
3.  问题是局部硬伤，还是整篇读者负担过高？局部硬伤可点修；整篇负担过高必须重跑 low cognitive burden rewrite。

## 6. 配图生成规范

配图是 external-facing 文章的**硬约束**。没有配图的外部文章不算完成，不得交付。短文（<2000 字）至少 1 张，长文（$\ge 2000$ 字）至少 2-3 张。

1.  **最终配图硬门槛**：任何进入 Markdown 的图片，最终嵌入文件都必须来自 **`gpt-image-2` 生成或重绘后的 PNG/JPG/WebP**。主线程绘制的 matplotlib 结构草稿、Mermaid、SVG 或 Keynote 导出等产物只能作为输入源，**不得直接作为最终配图引用**。
2.  **定量图表重绘**：主线程先用 matplotlib 绘制结构草稿保证数据准确 $\rightarrow$ 调用 Image Generation Skill 用 `gpt-image-2` 接收 matplotlib 草稿作为输入（`-i` 参数）进行视觉重绘。
3.  **视觉风格**：默认使用浅色背景、低饱和配色、典雅简洁的商务/研究报告风格。避免暗色背景、霓虹紫、高对比发光等装饰性光效。
4.  **体积限制**：生成后统一压缩为 **jpg/webp** 格式。单图体积必须控制在 **200KB** 以内（长边 1024 像素），禁止 base64 内联。

## 7. Post-writing 质量扫描检查

扫描范围由主线程底座模型决定（延续第 5 节的权限划分）：

- **Gemini 系列主线程**：跑下面全部 9 项扫描，文风类命中后按第 5.2 节三问 gate 决定点修还是重跑。
- **非 Gemini 主线程**：只跑 1（破折号，markdown 渲染硬伤）、7（图片引用语法）、8（中英混排硬伤）、9（无信息增量的双语括注）这四项**机械核查**，以及一遍**数字与链接核对**（对照 brief 的"数字精确性硬约束"和 inline links 清单）。第 2、3、5、6 项是文风扫描，不跑。第 9 项命中后应交回写作模型清理，不要由异种模型自行改写 prose。

文章成稿并通过配图生成后，主线程**必须强制执行对应范围的扫描**，严禁仅凭肉眼校对：

```bash
# 1. 破折号（成品严禁存在 ——）【所有主线程必跑】
rg -n '——' <file>

# 2.「很+形容词」判断总结（扫描到的一律删除，换事实填实）【仅 Gemini 主线程】
rg '很[直接清楚简单明显重要透彻全面深入关键]' <file>

# 3. 内部脚手架术语泄漏（扫描到的一律清除）【仅 Gemini 主线程】
rg 'L[0-6]|axiom|Phase [A-Z]|叙事重构|技术族谱|瓶颈迁移|Thesis Catalog' <file>

# 4. 英文 blockquote 超长审计（超 100 字符行需人工审查是否超 20 词或 3 个信息点）【仅 Gemini 主线程】
rg -n '^> ' <file> | awk '{ if (length($0) > 100) print }'

# 5. 元评论、评价性引导词与全文禁用表达审计（命中后一律删除或改为具体事实）【仅 Gemini 主线程】
rg -n '说得.{0,5}更|直白到|不需要转述|本身就说明|本身就有点|很容易漏掉|用不着在推理|值得|长出来|长出了|生长' <file>

# 6. 被动语态审计（逐个排查翻译腔，翻译腔被动语态一律改主动）【仅 Gemini 主线程】
rg -n '被' <file>

# 7. 图片引用核查（确保每个图片都是 gpt-image-2 重绘后的 jpg/webp，且包含 alt text，没有被反引号包裹成代码块）【所有主线程必跑】
rg -n '!\[[^\]]+\]\([^\)]+\)' <file>

# 8. 中英混排残留审计（扫描 "常规 of" / "能力 and 局限" 等硬伤）【所有主线程必跑】
rg -n '\b(of|and|the|to|in|for|with|or|but|is|are|was|were)\b' <file> | rg -v 'https?://|!\[|^\s*#\|^\s*>'

# 9. 无信息增量的双语括注（如“执行状态（execution state）”）【所有主线程必跑】
rg -n '[\p{Han}”’」』][（(][A-Za-z][A-Za-z0-9 _./+:-]{1,50}[）)]' <file> | rg -v 'https?://|!\['
```

## 8. 交付终点

写完并配好图片的最终 MD 文件，保留在本地工作区即为写作交付终点。主线程**严禁自动执行任何外发发布流程**（如 `yage_share`、博客上线、Twitter 自动发布、Circle 社区发布等）。发布动作需要等待用户的显式指令，将调研写作与发布决策完全解耦。
